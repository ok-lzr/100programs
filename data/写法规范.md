# 任务卡写法规范

> 这份规范管的是 `data/author/*.json` 里写什么、怎么写。
> 生成出来的东西有两处：项目文件夹里的 `README.md`（学生看的任务卡）和网站数据。
> 写完必须跑 `python tools/lint_author.py`，不过关的内容不允许生成。

## 一、一个项目文件的字段

| 字段 | 写什么 | 长度参考 |
| --- | --- | --- |
| `id` | 三位编号，必须和文件名、plan.json 一致 | `"011"` |
| `title` | 项目名，跟 plan.json 一致 | — |
| `summary` | 一句话说清这个程序干什么（网站上就显示这一句） | 15~30 字 |
| `why` | 为什么值得做：落到"做完你能拿它干什么"，不要讲技术意义 | 80~160 字 |
| `finish` | 做完是什么样：描述运行时的一问一答，带上大概行数 | 80~150 字 |
| `newStuff` | 这个项目新学的东西是哪一样（复习型就写"这是复习"） | 30~80 字 |
| `skills` | 会练到的语法清单，6~14 项，写名字不写代码 | 每项 2~12 字 |
| `filesLine` | 几个文件、大概多少行 | `"1 个文件（x.py），约 120 行"` |
| `hoursLine` | 建议工时 + 可以分几次做完 | `"2 ~ 3 小时，分 4 次"` |
| `libsLine` | 要不要装东西；要装就写清楚装什么 | `"只用自带功能"` |
| `levels` | 3~5 个关卡（见下） | — |
| `extend` | 做完之后的 3~5 个加练方向 | 每项 15~40 字 |
| `status` | 固定 `"ready"` | — |

## 二、一关必须有的六个部分

每一关都要齐，少一个 `lint_author.py` 会报错。

| 部分 | 字段 | 要求 |
| --- | --- | --- |
| 建议用时 | `time` | 20~40 分钟，超过 40 就说明这一关该拆 |
| **做出这样就算过** | `goal` | 必须**可观察**：写清运行后屏幕上出现什么、输入什么得到什么。含具体数字。不许写"掌握 xxx" |
| **怎么想（步骤）** | `steps` | 3~8 步，一步一步能跟着做。只讲思路和顺序，不讲语法细节 |
| **要用到的语法点** | `syntax` | 2~7 条，每条 `{name, hint}`。`name` 是语法名（可以有 `time.sleep()` 这种 API 名），`hint` 用人话说它是干嘛的 |
| **做完了自己检查** | `check` | ≥3 条，每条都能手工验证，必须包含边界值（0、负数、空输入、超长输入） |
| **卡住看这里** | `stuck` | ≥2 条，写"症状 → 去哪看/怎么排"，不要重述步骤 |
| **常见坑** | `pitfalls` | ≥1 条，写真正会踩的坑，不写"要小心"这种废话 |

## 三、不可以出现的东西

**不许有能直接跑的代码。** 判定的边界：

- ❌ 赋值语句（`x = 5`）
- ❌ 带参数的函数调用（`print(x)`、`open("a.txt")`）
- ❌ 关键字开头、冒号结尾的整行语句
- ❌ f-string 字面量、类型注解箭头、`self.`、代码块围栏
- ✅ **允许**：只有名字的 API 提及 —— `print`、`input`、`time.sleep()`、`.strip()`、`random.choice`
- ✅ **允许**：演示输出 —— `100.00°C = 212.00°F`、`150 厘米 = 1.5 米`、`共 24 行，成功 23 行`

一句话判别法：**把这行照抄进编辑器能跑起来吗？能跑就是代码，不能跑就是说明。**

## 四、关卡怎么切

1. **每一关单独跑都能看到效果。** 这是硬要求——一关做完必须有东西出现在屏幕上。
2. **难度只往上走。** 前一关是这一关的地基；同一关里不要出现还没学的东西。
3. **最后一关通常是"整合"**：加循环、加菜单、存文件、做成函数、处理异常，把前几关拼成一个完整的程序。
4. **第一关要最短最简单**，20 分钟内能跑出第一行输出，先给成就感。
5. 复习型项目（001~010）的关卡要落在"以前学过的语法"，新东西只占一小部分。

## 五、难度与体量对应

| 阶段 | 编号 | 难度 | 体量 | 依赖 |
| --- | --- | --- | --- | --- |
| 找回手感 | 001–020 | 1.0~2.0 | 单文件 100~150 行 | 只用标准库 |
| 联网与窗口 | 021–040 | 2.0~2.5 | 1~2 个文件，150~200 行 | 最多装 1 个库 |
| 素材与数据 | 041–060 | 2.5~3.5 | 2~3 个文件，200~250 行 | 可装库 |
| 采集与网站 | 061–080 | 3.5~4.5 | 3~5 个文件，250~300 行 | 可装库 |
| 完整作品 | 081–100 | 4.5~5.0 | 最多 6 个文件，**单文件 ≤300 行** | 可装库 |

## 六、语气

- 对**一个初二学生**说话，用"你"，像坐旁边一起写。
- 不用"用户 / 需求 / 实现 / 部署 / 本项目 / 综上所述"这类词。
- 不喊口号（"加油！你一定可以！"），也不贬低（"这么简单都不会"）。
- 讲坑的时候说人话：不是"注意类型错误"，而是"拿文字去做乘法，Python 会报 TypeError"。
- 允许口语，但每句话都要有信息量。

## 七、写完必须做的事

```bash
python tools/lint_author.py 011      # 只查这一份
python tools/build.py                # 体检不过关会拒绝生成
python tools/checkin.py 011          # 看关卡有没有正确生成出来
```

## 八、几种典型的写坏

| 写坏了 | 长什么样 | 怎么修 |
| --- | --- | --- |
| 写成教程 | 把语法从零讲一遍，一大段概念 | 概念交给教程，任务卡只给"这关要什么效果 + 思路 + 该用哪个语法" |
| 写成需求书 | "必须支持 6 种格式、异常处理、日志" | 一条需求只留一个可观察的目标，其余挪到 `extend` |
| 关卡不连续 | 第 2 关突然要用第 4 关才学的东西 | 每关只依赖前面出现过的语法 |
| 目标不可观察 | "理解字典的用法" | 改成"运行后打印出每个词出现几次" |
| 一步到位 | 一关就要写完整个程序 | 第一关先让它输出一行结果，后面再逐步加交互、循环、存文件 |
| 提示里藏代码 | "写 `for i in range(10):`" | 改成"用一个数 10 次的循环（range）" |
