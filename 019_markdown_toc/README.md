# 019 · Markdown 目录生成器

> ★½☆☆☆　难度 1.5 / 5　·　001–020 · 找回手感
> 2 ~ 3 小时，分 4 次　·　1 个文件（md_toc.py），约 150 行　·　只用 Python 自带功能
>
> **规矩：这份任务卡只给思路和语法点，一行代码都没有。代码由你自己写。**

**一句话**：扫描标题层级，给笔记自动生成一份可点击的目录

## 为什么做它

用 Markdown 写笔记写得越长，越需要一个目录：不然想找「第三章第二节」只能一路滚。手工维护目录是最烦的事——加了新标题就忘了改目录。这个项目做的就是让它自动生成，而且能在原地更新，你以后写笔记、写项目说明都用得上（第 058 个静态博客也会用到同样的思路）。

## 做完是什么样

程序扫描一个 Markdown 文件，把所有标题按层级抽出来，生成一份带缩进和序号、每个条目都能点着跳转的目录；能直接插进原文的指定位置（用一对标记包住，下次更新只换中间那一段）；也能一次处理一整个文件夹里的所有 Markdown，改之前先备份。约 150 行，一个文件。

## 会练到的语法

`逐行读取`　`字符串开头判断`　`统计井号个数`　`去掉多余空白`　`按层级缩进`　`字符串替换生成链接`　`列表组装与连接`　`字符串查找与切片`　`批量遍历`　`备份文件`

> 新东西是「标记区块」：在文件里放一对特殊注释当围栏，程序只替换围栏之间的内容。这是所有「自动生成但写在原文件里」的工具（目录、目录树、时间戳）通用的一招。

## 关卡 1 · 先把标题找出来

**建议用时**：20 分钟

### 做出这样就算过

程序读一个 Markdown 文件，把里面所有标题行打印出来，每行前面标出它是第几级：一级标题显示「1 级」，二级显示「2 级」。最后打印「共找到 12 个标题」。

### 怎么想（步骤）

1. 新建 md_toc.py，先手写一个测试用的 Markdown 文件：里面有不同层级的标题、有正文、有列表，还故意放一个正文里带井号但不在行首的行
2. 逐行读文件，判断这一行是不是标题：Markdown 里标题是以井号开头的，而且井号要紧挨着行首
3. 数一数开头有几个连续的井号，那个数字就是层级
4. 把井号和后面的空格去掉，剩下的就是标题文字
5. 把结果打印出来，核对一下有没有把正文里带井号的行误判成标题

### 要用到的语法点

- **逐行读取**：打开的文件可以直接一行行遍历，不用先读成一大段
- **判断开头**：字符串有现成的「是不是以某内容开头」的判断
- **去掉行首字符**：去掉开头的井号和空格，去掉两头的空白，剩下的才是标题
- **数连续字符**：用循环数开头有几个井号；也可以先去掉一边再看长度差
- **跳过空行**：空行和纯空白行先跳过，不然会算进统计里

### 做完了自己检查

- [ ] 所有标题都被找出来了，级别正确
- [ ] 正文里带井号的行没有被误判（这是这一关最重要的检查）
- [ ] 标题前后的空格被去掉了
- [ ] 一级标题的数量跟你自己数的一致
- [ ] 文件不存在时给提示不崩

### 卡住看这里

- 正文里的井号也被当成标题：只判断「以井号开头」还不够，还要确认井号前面没有别的内容
- 层级全都算成 1：数井号时用了判断而不是计数
- 标题文字里还带着井号：去掉井号的那一步没做干净

### 常见坑

- 用「包含井号」当判断条件（正文里出现井号也会被算进来）
- 把 Markdown 里用井号写的注释也当成标题（先不用管，知道有这回事就行）

## 关卡 2 · 排成一份有层次的目录

**建议用时**：30 分钟

### 做出这样就算过

输出一份目录：按标题出现的顺序，层级越深缩进越多（每级缩进两个空格），每行前面带序号，序号形式是 1、1.1、1.2、2 这种跟着上一级走。用你自己的笔记测试，看起来像一份真正的目录。

### 怎么想（步骤）

1. 想清楚编号规则：一级标题重新起一个大号，二级标题跟在它下面编小号，三级再往下。用一个列表记录每一层当前的编号
2. 每遇到一个标题：把当前层级的编号加一，并且把它下面所有层级的编号清零（不然上一章的小号会串到下一章）
3. 缩进量等于「层级减一」乘两个空格；用字符串乘法比写循环清楚
4. 把编号拼起来（比如 2.3），再加上标题文字，组成一行
5. 全部攒进列表，最后统一打印或者写文件

### 要用到的语法点

- **用列表存每层编号**：列表的第 0 项是一级标题的编号，第 1 项是二级的，依此类推
- **编号加一与清零**：遇到某一级时，这一级加一，它下面所有级别都归零
- **拼编号**：把用到的那几层编号用点连起来
- **缩进用字符串乘法**：空格字符串乘层级数
- **列表收集后统一输出**：先全都攒起来，最后决定打印还是写文件

### 做完了自己检查

- [ ] 编号规则正确：1、1.1、1.2、2、2.1 这样走
- [ ] 新的一级标题出现时，二级编号从 1.1 重新开始
- [ ] 缩进层级跟标题层级一致
- [ ] 只有一级标题的文件也能正常生成
- [ ] 目录里的标题顺序跟原文完全一致

### 卡住看这里

- 二级编号一直累加不重置：遇到新的一级标题时忘了把下面的编号清零
- 第一行是 0：编号从 0 开始，起始值要设成 1
- 缩进量不对：层级是从 1 开始的，算缩进时记得减一

### 常见坑

- 用固定的几层变量（一层一个变量）写死，遇到第四级标题就出错——用列表才不限层数
- 缩进用制表符，不同编辑器显示宽度不一样，用空格更稳

## 关卡 3 · 做成能点的链接

**建议用时**：30 分钟

### 做出这样就算过

运行后生成的目录里，每个条目都能点击跳转到对应的标题；把目录写进一个新文件，用阅读器打开点几个条目验证。锚点规则你自己定，但要满足两条：同一个文件里不重复、跟常见阅读器的规则基本一致（小写、空格换成短横线）。

### 怎么想（步骤）

1. 定一条锚点规则，比如：标题文字全体转小写、去掉标点、空格换成短横线
2. 处理重复：同一个标题可能出现两次，第二次后面加个 -2、-3，保证不重复
3. 每一行拼成「缩进 + 序号 + 标题（链接）」的形式，链接部分用方括号包文字、圆括号包锚点
4. 把整个目录用换行连起来，写进一个新文件（先别动原文件）
5. 用阅读器打开那个新文件，点几个条目验证真的能跳

### 要用到的语法点

- **转小写与替换**：先统一小写，再把空格换成短横线，都是一行就能做的事
- **去掉标点**：把标点逐个替换成空内容；中文标点和英文标点是两套，都要处理
- **用字典记重复次数**：锚点当键、出现次数当值，第二次出现时就知道该加后缀了
- **拼 Markdown 链接**：方括号里放显示文字，圆括号里放锚点，中间不要留空格
- **写入文件**：指定编码，用换行把列表连起来一次写完

### 做完了自己检查

- [ ] 点目录里的条目能跳到对应标题
- [ ] 有重名标题时锚点自动带上了后缀，两个都能跳
- [ ] 标题里有中文、数字、标点时锚点也没出错
- [ ] 锚点里没有空格和大写字母
- [ ] 写出来的文件在阅读器里显示成一份正常目录

### 卡住看这里

- 点了跳不过去：把生成的锚点和阅读器实际用的锚点对比一下（阅读器一般也是同一套规则）
- 两个同名标题跳的是同一个地方：重复计数没做，或者计数变量在循环里被重置了
- 锚点里保留了中文标点：标点处理只做了一半

### 常见坑

- 把锚点规则写得太复杂（阅读器不认），简单的「小写 + 空格换短横线 + 去标点」最兼容
- 忘了锚点不能有大写字母（有的阅读器区分大小写）

## 关卡 4 · 原地更新，还要能批量处理

**建议用时**：35 分钟

### 做出这样就算过

程序能直接把目录插进原文件：找到一对固定标记（比如两行注释），只替换它们之间的内容，标记之外一个字都不改；标记不存在时把目录插到文件开头。再加一个批量模式：处理一整个文件夹里的所有 Markdown，每个文件改之前先备份成 .bak。

### 怎么想（步骤）

1. 定一对标记：开始标记和结束标记各占一行。程序要把整份文件按这两行切成三段：前面、中间（旧目录）、后面
2. 替换时只重建中间那一段，前面和后面原样拼回去。这样你写在文档末尾的内容绝不会被动到
3. 找不到标记时：把新目录插在文件最前面（标题之后），并提示用户「这个文件没有标记，我插在开头了」
4. 批量模式：遍历文件夹里所有 Markdown，逐个处理；处理前把原文件复制一份加 .bak 后缀
5. 跑完打印汇总：处理了几个、跳过几个、有几个没有标记

### 要用到的语法点

- **按标记切分**：先把整份文件读成一段文字，找到两个标记的位置，用切片取三段；找不到标记时切片会失败，要先判断
- **字符串查找**：判断某个标记在不在文本里，有现成方法
- **切片保留两端**：用位置把文本切成前后两段，中间那段丢掉，再拼上新目录
- **复制文件**：改之前复制一份做备份，出错能马上还原
- **批量遍历并汇总**：遍历文件夹，逐个处理，用几个计数器记录结果

### 做完了自己检查

- [ ] 有标记的文件被正确更新，标记之外的文字一个字符都没变（用备份对比）
- [ ] 没有标记的文件目录被插到开头，并有提示
- [ ] 重复运行结果稳定：第二次生成的目录跟第一次一样，不会越插越多
- [ ] 备份文件确实存在
- [ ] 批量模式跳过了 .bak 文件和文件夹

### 卡住看这里

- 标记之外的文字被改动了：你可能用「替换整份文件」的方式写回，应该只重建中间那一段
- 第二次运行目录变两份：结束标记没找到，程序把新目录又插了一遍
- 备份文件被当成 Markdown 又处理了一遍：批量时要过滤掉 .bak 后缀

### 常见坑

- 没有备份就直接原地改（这是所有「自动改我自己文件」的工具必须有的保命措施）
- 用标记的第一处和最后一处切片（如果文件里有多对标记就会切错，要取最近的一对）
