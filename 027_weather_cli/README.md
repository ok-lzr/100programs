# 027 · 天气查询命令行工具

> ★★☆☆☆　难度 2.0 / 5　·　021–040 · 联网与窗口
> 3 小时左右，分 4 次　·　1 个文件（weather.py），约 160 行　·　只用 Python 自带功能（接口免费且不需要注册）
>
> **规矩：这份任务卡只给思路和语法点，一行代码都没有。代码由你自己写。**

**一句话**：查长沙现在多少度，多个城市都行，还能缓存省流量

## 为什么做它

这是你第一个**吃真实数据**的程序：数据不在你电脑上，而在别人的服务器上，通过网络现取。你会踩到所有联网程序都会踩的坑——网络会断、接口会变、数据格式可能不是你想要的。做完它，你手机上的天气应用对你来说就不再是黑盒子了。

## 做完是什么样

程序输入城市名（内置一张常用城市的经纬度表），显示现在的温度、风速和天气状况（把接口给的天气代码翻译成人话，比如「多云」「小雨」）；把结果缓存在文件里，十分钟内再查同一个城市直接用缓存；断网时显示上次的缓存并注明「这是 xx 分钟前的数据」。约 160 行，一个文件。

## 会练到的语法

`urllib 请求接口`　`URL 拼参数`　`JSON 解析`　`字典逐层取值`　`代码对照表`　`缓存文件`　`时间比较`　`异常降级`　`输入校验`　`写报告`

> 新东西是「接口」：别人提供的一个网址，你按它的规矩传参数，它给你一段 JSON 数据。这是程序之间交换数据最通用的方式。

## 关卡 1 · 先拿到一个温度

**建议用时**：30 分钟

### 做出这样就算过

运行后输出「长沙现在 19.8 度」，数字是真的（可以拿手机上的天气对比一下，允许有一点点差异，因为观测点不同）。

### 怎么想（步骤）

1. 这一关的重点是先看懂接口：用浏览器打开这个免费天气接口的文档页（搜索「open-meteo 天气接口」，它有中文页面），找到「当前天气」那一节，看清它要哪些参数
2. 需要三个参数：纬度、经度、时区。长沙大概是北纬 28.2、东经 112.9。注意参数是拼在网址后面的，网址和参数之间用问号，参数之间用和号隔开
3. 在浏览器里先把完整网址打开一次，亲眼看到返回的 JSON 长什么样——**这一步千万别跳过，先看清楚数据结构再写代码**
4. 在程序里请求这个网址，把返回内容解析成字典，然后一层层把温度取出来（数据是嵌套的，先取 current 那一层，再取温度字段）
5. 打印温度。如果取不到，先把整个返回内容打印出来，看看你猜的层级对不对

### 要用到的语法点

- **请求接口**：和请求网页是一样的方式，只是返回的是一段 JSON 文字
- **拼参数**：网址后面加问号，参数写成名字加等号加值，多个参数用和号连接
- **解析 JSON**：把返回的文字交给自带功能，它就变成字典和列表
- **逐层取值**：嵌套字典要先取外层再取内层；中间那层的名字从接口文档上抄
- **打印结构**：取不到值时先打印整个字典，比对着猜快得多

### 做完了自己检查

- [ ] 温度能取到，数量级合理（十几到三十几度）
- [ ] 结果跟手机天气大致对得上
- [ ] 把纬度改掉之后温度跟着变（说明参数真的生效了）
- [ ] 把参数名写错时程序给出提示而不是甩一串报错
- [ ] 整个过程两三秒内出结果

### 卡住看这里

- 返回内容看不懂：先把它打印出来，或者复制到能格式化 JSON 的工具里看一眼层级
- 取值时报「键不存在」：层级或字段名跟接口文档不一致（接口偶尔会调整，以文档为准）
- 请求超时：给请求加上超时参数，别一直等

### 常见坑

- 不看接口文档就开始写代码（字段名靠猜，通常一次猜不对）
- 把「当前天气」和「天气预报」两个不同的数据块搞混（我们在这一关只取当前的）

## 关卡 2 · 把数据翻译成人话

**建议用时**：30 分钟

### 做出这样就算过

输出变成三行：温度 19.8 度、风速 20.7 公里每小时、天气 多云。天气那一项要是人话，不是数字。再判断一次：如果温度低于 10 度，多输出一句「今天挺冷，穿厚点」。

### 怎么想（步骤）

1. 接口给的天气状况是一个数字代码，需要在接口文档里找到「天气代码对照表」，把常用的十几个抄进程序里做成一张表
2. 写一个翻译函数：给它代码，返回中文描述；表里没有的代码就显示「未知天气（代码 45）」
3. 把风速也显示出来，注意看文档里风速的单位是什么，显示时把单位写清楚
4. 取值时用「取不到就给默认值」的方式，避免接口少给某个字段时程序崩掉
5. 加一句贴心的判断：温度低、风速大的时候多给一句提醒

### 要用到的语法点

- **字典当对照表**：代码当键、中文当值，查不到时给一个带原始代码的默认描述
- **翻译函数**：输入代码输出人话，函数里只做查表，不负责打印
- **取值给默认值**：字段可能不存在，用带默认值的取值方式最稳
- **格式化输出**：温度保留一位小数，单位写在数字后面
- **条件提醒**：用判断给出一句额外建议，注意别把话说得像天气预报员

### 做完了自己检查

- [ ] 天气显示的是中文而不是数字
- [ ] 对照表里没有的代码会显示代码本身，方便你回头补
- [ ] 把某个字段从返回里删掉（手工改一下测试数据）程序也不崩
- [ ] 温度低于 10 度时确实多出那句提醒
- [ ] 三行输出对齐，单位清楚

### 卡住看这里

- 查表总是查不到：注意键的类型（代码是数字，别拿字符串去查，或者查之前统一转一下）
- 显示成「未知天气」但你知道它是什么：去接口文档把那个代码补进表里
- 想显示更多信息：先看清楚文档里有哪些字段，别去猜字段名

### 常见坑

- 把代码直接当描述打印（对用户来说「3 度」和「3 号天气」完全不是一回事）
- 把所有代码都抄下来（几百个代码没必要，先抄常用的，遇到新的再补）

## 关卡 3 · 支持多个城市

**建议用时**：30 分钟

### 做出这样就算过

程序运行时可以在后面带上城市名，比如查长沙、北京、上海、广州各得到正确结果；输入一个没收录的城市名，程序提示「没有这个城市的坐标，目前支持：……」并不崩；不带城市名时默认查长沙。

### 怎么想（步骤）

1. 内置一张城市表：城市名对应一组经纬度，先放五六个你关心的城市（顺便练习怎么去查一个城市的经纬度）
2. 从运行参数里取城市名；没有参数就用默认值
3. 城市名查表：查不到时列出所有支持的城市名，这一句提示要写清楚
4. 把「取经纬度」和「查天气」分开成两个函数，主流程负责串起来
5. 一次查多个城市：允许在参数里写多个城市名，循环查询，每个城市输出一小段

### 要用到的语法点

- **读运行参数**：运行时写在后面的内容可以从运行参数里拿到，是一串字符串
- **默认值**：没有参数时用一个默认城市，程序不会因为少写参数就崩
- **嵌套字典查表**：城市名当键，值是一组经纬度；查不到时把所有的键列出来提示用户
- **函数拆分**：取坐标和查天气各一个函数，主流程负责组合
- **循环多城市**：遍历参数里的城市名，逐个查询打印

### 做完了自己检查

- [ ] 查长沙、北京、上海各得到合理的温度（南北差异要能看出来）
- [ ] 不带参数时默认查长沙
- [ ] 输入「火星」时列出所有支持的城市，程序不崩
- [ ] 一次传两个城市能都查到
- [ ] 同一个城市连续查两次结果一致（或差异极小）

### 卡住看这里

- 参数里有空格导致查不到：输入时给城市名加引号，或者程序里把空格去掉
- 不同城市温度一样：参数没真的传进去，检查拼网址时经纬度有没有替换成功
- 中文城市名在参数里出问题：先用一个中文城市表在程序内部查，别把中文直接拼进网址

### 常见坑

- 每次查询都硬编码一个城市（程序就没法通用了）
- 把城市表的经纬度记错（南北半球差一个符号，温度会差到离谱）

## 关卡 4 · 加缓存，断网也能看

**建议用时**：30 分钟

### 做出这样就算过

程序把查到的结果连同时间一起存进缓存文件；十分钟内重复查同一个城市直接读缓存（并在输出里说明「来自缓存」）；断网时显示缓存里的数据并注明「这是 7 分钟前的数据」；缓存文件不存在或者被改坏了，程序照常联网查询，不崩。

### 怎么想（步骤）

1. 缓存结构：一个 JSON 文件，键是城市名，值是「数据 + 记录时间」
2. 查询前先看缓存：有数据且时间在十分钟内，直接用；否则联网查并更新缓存
3. 时间比较：把记录时间从文字解析回时间对象，跟现在相减，看差了多少分钟
4. 断网降级：联网失败时，如果缓存里有这个城市的数据，就显示它并说明是多久之前的；没有就如实说查不到
5. 缓存文件读写都要接住异常：文件不存在、内容被手改坏了，都当作「没有缓存」处理
6. 打印时明确标注数据来源：实时 还是 缓存（多久前）

### 要用到的语法点

- **缓存文件结构**：用一层字典包住：外面是城市名，里面是数据和记录时间
- **时间解析与比较**：把记录的时间文字解析成时间对象，跟现在相减得到时间差
- **取时间差**：时间差对象里能取出总秒数，除以 60 就是分钟
- **写入缓存**：每次查完就更新这个城市的那一条，其它城市保留
- **读写异常兜底**：文件不存在或格式坏了都当成没有缓存，让程序继续能联网查

### 做完了自己检查

- [ ] 第一次查是实时的，马上再查一次显示「来自缓存」
- [ ] 把缓存文件里的记录时间手工改成很久以前，程序会重新联网查
- [ ] 断网后查一个缓存里有的城市，能显示出来并注明是多久之前的
- [ ] 断网后查一个缓存里没有的城市，如实提示查不到，不崩
- [ ] 把缓存文件写坏，程序照样能跑（当作没缓存）

### 卡住看这里

- 时间差算出来是负数：记录时间的格式或时区跟现在不一致，先把两个时间都打印出来看
- 缓存永远命中：时间比较写错了，比如拿到了小时数却当分钟用
- 缓存文件被覆盖成只有一个城市：更新时没有先把旧缓存读进来

### 常见坑

- 缓存时间设得太长（拿半小时前的数据当实时，用起来会误事）
- 把缓存当成数据源，联不上网就一直吃老数据还不告诉用户（必须注明是旧数据）
