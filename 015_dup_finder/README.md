# 015 · 重复文件查找器

> ★½☆☆☆　难度 1.5 / 5　·　001–020 · 找回手感
> 3 小时左右，分 4 次　·　1 个文件（dup_finder.py），约 170 行　·　只用 Python 自带功能
>
> **规矩：这份任务卡只给思路和语法点，一行代码都没有。代码由你自己写。**

**一句话**：找出一个文件夹里内容一样的文件，算出能省多少空间

## 为什么做它

照片备份了两次、资料下载了两遍、同一份作业存在三个文件夹里——这些重复文件占着你几百兆空间，但你不可能一个个去比。手工比是不可行的，所以这个项目要教你三种越来越快的比较办法，最后一种是所有网盘「秒传」功能背后的原理。

## 做完是什么样

程序扫描一个文件夹，找出所有内容重复的文件：按组显示，每组里第一个是「保留」的，其余是「多余的」；算出这些多余的加起来占多少空间、能省多少；还能把它们移到一个叫「待删」的文件夹里（**不是直接删**）。约 170 行，一个文件。

## 会练到的语法

`字典分组`　`取文件大小`　`二进制方式读文件`　`分块读取`　`import hashlib`　`十六进制字符串`　`列表切片`　`移动文件`　`大小累加与换算`　`写入报告`

> 新东西是「用哈希代替逐字节比较」：给文件内容算一个指纹，指纹一样就是同一个文件。这也是你第一次接触「指纹/校验」这个概念。

## 关卡 1 · 先按大小把可疑的挑出来

**建议用时**：25 分钟

### 做出这样就算过

扫描一个文件夹，找出「大小完全一样」的文件并分组打印：每组先显示大小，再列出同组的所有路径。只有一个文件的组不显示。最后打印「发现 3 组可疑」。

### 怎么想（步骤）

1. 新建 dup_finder.py，准备一个测试文件夹：手工造几对内容相同的文件（复制粘贴即可），再放几个大小不同的当干扰
2. 遍历文件夹里的所有文件，把文件大小取出来
3. 用字典按大小分组：键是大小，值是一个装着路径的列表。分组的时候要处理「这个大小第一次出现」的情况
4. 遍历这个字典，把长度大于 1 的组打印出来
5. 最后统计有多少组。注意：这里只是「可疑」，大小一样不代表内容一样

### 要用到的语法点

- **字典按大小分组**：值是列表的字典，可以表示「这个大小对应哪些文件」；第一次遇到某个键时要先建一个空列表
- **取文件大小**：路径对象上的 stat 里有大小字段，单位是字节
- **只挑文件**：遍历时跳过文件夹，只看文件
- **遍历字典**：同时拿到键和值，比先取键再取值少写一行
- **过滤结果**：只打印组内文件数大于 1 的组

### 做完了自己检查

- [ ] 造好的重复文件被分到了同一组
- [ ] 大小不同的文件没有混进来
- [ ] 只有一个文件的组不显示
- [ ] 空文件夹跑起来不崩，输出「没有发现可疑」

### 卡住看这里

- 报错说字典键不存在：分组前要先判断这个大小有没有出现过
- 什么都没找到：检查测试文件夹里是不是真的放了内容相同的文件
- 把文件夹也算进去了，导致大小对不上

### 常见坑

- 以为大小一样就是重复——不同内容也可能恰好一样大，下一关才见分晓
- 拿重要的文件夹来扫描（这一关只读不改，但还是建议用测试文件夹）

## 关卡 2 · 大小一样还不够，要比内容

**建议用时**：30 分钟

### 做出这样就算过

对每个可疑的组，进一步比较内容，只把真正一样的算作重复。比较时按「一块一块读」的方式做，并且一旦发现不同就立刻停止，不再读完整个文件。最后打印真正重复的组。

### 怎么想（步骤）

1. 写一个比较两个文件内容的函数：给它两个路径，返回它们是不是一样
2. 先比大小（大小不同直接返回不同，省时间），再用二进制方式一次读一块（比如 8KB），逐块比较
3. 只要有一块不同就立刻返回「不一样」——不用坚持读完，这就是这个函数快的原因
4. 把每组里的文件依次跟「组内第一个」比较，内容一样的归到一个子组里
5. 拿两组测试：一组是真重复，一组是大小一样但内容不同（自己造：同样长度的两段不同文字）

### 要用到的语法点

- **二进制方式打开**：读文件时用二进制模式，这样图片、压缩包这类也能读，不受编码影响
- **分块读取**：一次读固定长度，读完了再读下一块，直到读出空内容为止
- **提前返回**：函数里一旦确定结果就立刻返回，不用跑完整个流程
- **比较字节**：两块内容直接用相等比较，Python 会帮你逐字节比
- **处理文件读不了的情况**：文件被别的程序占用时读取会失败，接住异常并跳过这个文件

### 做完了自己检查

- [ ] 真重复的文件被判为重复
- [ ] 大小相同但内容不同的两个文件没有被误判（这是这一关的关键测试）
- [ ] 扫描一个大文件时程序不会卡很久（因为分块比较会提前退出）
- [ ] 文件读取失败时程序跳过它继续跑
- [ ] 结果跟上一关的「可疑组」数量对比：真正的重复组应该更少或相等

### 卡住看这里

- 全都判成了不重复：检查两个文件的读取位置是不是都从头开始的
- 误判成重复：确认你比的是内容，不是名字也不是大小
- 程序很慢：你可能把整个文件一次读进来了，改成分块

### 常见坑

- 用文本方式打开去读图片，导致读取失败或内容被改
- 比较时只比了第一块就下结论（除非块大小覆盖了全文）

## 关卡 3 · 用哈希一次算出指纹

**建议用时**：35 分钟

### 做出这样就算过

改用哈希来判重：给每个文件算一个哈希值（内容指纹），指纹一样就算重复。要求逐个文件只读一遍，而不是两两互相比较；输出指纹的前 12 位方便肉眼核对。一个 100 个文件的文件夹，运行时间要明显比上一关短。

### 怎么想（步骤）

1. 想清楚为什么哈希更快：上一关是「两两比较」，10 个文件可能要比较几十次；哈希是每个文件只读一遍算一个指纹，然后按指纹分组
2. 引入自带的哈希功能，选一种常用的算法（比如 sha256）
3. 分块读取文件并不断把内容喂给哈希对象，全部读完后再要最终的指纹
4. 把指纹当字典的键分组（跟第一关按大小分组是一样的套路），然后只打印组内多于一个的
5. 先在测试文件夹上跑，再找一个真实文件夹跑，感受一下速度

### 要用到的语法点

- **import hashlib**：自带模块，能算好几种哈希；sha256 是常用的那种
- **创建哈希对象**：先用算法名造一个对象，再把内容一段段喂给它
- **边读边喂**：不需要把整个文件读进内存，读一块喂一块，大文件也不怕
- **取指纹**：全部喂完后向对象要一个十六进制的字符串，那就是指纹
- **按指纹分组**：和按大小分组完全一样的写法，只是键换成了指纹

### 做完了自己检查

- [ ] 内容相同的文件指纹完全相同
- [ ] 内容只差一个字的文件指纹完全不同（这是哈希最该有的性质）
- [ ] 结果跟上一关的真重复组一致
- [ ] 扫描速度比上一关快（可以用时间功能粗略计时对比）
- [ ] 打印指纹前 12 位，跟另一台机器上算的能对上

### 卡住看这里

- 指纹每次都不同：你把哈希对象建在了循环里面，每个文件都重新开始算
- 大文件内存暴涨：读文件时用了「一次读完」的写法，改成分块
- 结果和上一关不一样：先检查是不是有文件在读取时被跳过了（异常被静默吞掉）

### 常见坑

- 把文件名也算进哈希（那样内容相同但名字不同的文件就判不出来了）
- 拿哈希直接当「文件内容」用——它只是指纹，不是原文，两个不同内容理论上也可能撞上同一个指纹

## 关卡 4 · 出报告，并安全地清理

**建议用时**：35 分钟

### 做出这样就算过

程序输出一份报告：每组列出所有路径、文件大小、这组多余的文件占多少空间；全部加起来算出「可以释放 23.4 MB」。另外支持把多余的那些**移动**到一个叫「待删」的子文件夹里（保留原来的相对路径），移动前要打印清单并让你确认。

### 怎么想（步骤）

1. 报告部分：每组里保留第一个（可以按修改时间最早的保留，或者就按顺序第一个），其余的算作多余
2. 多余额 = 组内多余文件个数减一，乘以单个文件的大小；把每组的多余额加起来得到总数
3. 写一个换算函数，把总字节数显示成 KB 或 MB（大于 1024 就进一级）
4. 移动功能：在目标文件夹里建一个「待删」子文件夹，按原来的相对路径重建目录再移动过去——**千万别直接删除**
5. 移动前打印将要移动的文件清单并询问确认；移动过程里任何失败都要继续处理剩下的并汇总结果

### 要用到的语法点

- **列表切片保留第一个**：从头到尾取一段，跳过第一个，剩下的就是多余项
- **累加与换算**：把每组的多余额加起来，最后统一换算单位显示
- **创建目录**：目标目录可能不存在，建目录时要允许「已经存在就不报错」
- **移动文件**：自带功能可以移动文件；移动前要保证目标文件夹已经建好
- **二次确认**：把用户输入统一成小写再比较，只有明确的肯定才动手
- **逐项容错**：移动失败的记下来，继续处理剩下的，最后一起汇报

### 做完了自己检查

- [ ] 报告里的每组、每个大小、总计都正确（自己拿两个文件乘一下核对）
- [ ] 可以释放的空间换算成 MB 后保留一位小数
- [ ] 移动后原位置的文件确实不在了，待删文件夹里能找到它们
- [ ] 拒绝确认时一个文件都不动
- [ ] 移动失败（比如文件被占用）时程序继续处理其它文件并汇总

### 卡住看这里

- 移动报错说目标目录不存在：移动之前必须先把目录建出来
- 待删文件夹被自己扫描进去了：扫描时要跳过这个文件夹，否则下次运行会把待删里的文件又算一遍
- 总大小对不上：注意「可以释放」只算多余的那部分，不是整组的大小

### 常见坑

- 直接删除文件（不可恢复）——这一关的全部意义就是「先移走、确认无误再删」
- 移动时只用了文件名，导致不同文件夹里的同名文件互相覆盖（要保留相对路径）
