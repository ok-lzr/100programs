**一句话**：掷骰子、算概率分布、随机点名、随机分组

## 为什么做它

随机是编程里最反直觉的一块：你觉得「随机」应该很均匀，但真掷 100 次 6 面骰子，各点数出现次数往往差得挺明显——这个项目会逼你亲手看到这件事。做完之后你还顺手得到两个班里能用的工具：随机点名和随机分组。

## 做完是什么样

程序能掷任意个任意面数的骰子并给出总和，还支持像「2d6+3」这样的写法（扔两个六面骰再加三）；掷很多次之后能画出每个点数出现的次数；另外还能从一份名单里随机抽一个人，或者把名单随机分成几组。约 160 行，一个文件。

## 会练到的语法

`random.randint / choice / sample / shuffle`　`while 循环`　`累计求和`　`字符串切分与类型转换`　`字典统计`　`列表操作`　`函数与参数`　`多重赋值`

## 关卡 1 · 先掷一个骰子

**建议用时**：15 分钟

### 做出这样就算过

运行后输出 1 到 6 之间的一个整数；连跑十次，六个数都会出现，而且不会出现 0 或 7。

### 怎么想（步骤）

1. 新建 dice.py
2. 引入 Python 自带的 random 功能
3. 用随机整数函数生成 1 到 6 之间的一个数，注意上下界都要包含在内
4. 打印结果，标注这是第几次掷
5. 连跑十次，数一数六个点数各出现了几次（用纸笔记也行）

### 要用到的语法点

- **random.randint**：生成指定范围内的随机整数，两个端点都包含；还有一个类似的函数端点不包含，别用错
- **print 多个内容**：逗号分隔可以一次打印几个东西

### 做完了自己检查

- [ ] 十次结果都落在 1 到 6
- [ ] 没有出现过 0 或 7
- [ ] 至少出现过两个不同的点数

### 卡住看这里

- 老是掷出 1？检查范围写成了 0 到 1 之类
- 想确认是真随机：把范围改成 1 到 2 掷二十次，两种结果都会出现才算对

### 常见坑

- 用错了随机函数，导致上限取不到（永远是 1 到 5）
- 把随机结果赋给变量却忘了打印，看不到输出

## 关卡 2 · 一次掷好几个，还要看分布

**建议用时**：30 分钟

### 做出这样就算过

程序问你掷几个骰子，输入 3 就先打印三次单次点数，再打印总和；再加一个「重复掷 1000 次」的功能，输出每个点数各出现了多少次（1 到 6 的次数加起来应该正好等于 1000）。

### 怎么想（步骤）

1. 用 input 拿骰子个数，转成整数并做基本校验
2. 用一个循环掷这么多次，每次把点数打印出来，同时累加到一个总和变量里
3. 循环结束后打印总和。先验算：3 个骰子的总和一定在 3 到 18 之间
4. 再做分布统计：准备一个空字典，循环 1000 次，每次掷一个骰子并把结果记一次数（字典计数的套路，跟你做 005 时用过的一样）
5. 把字典里六个点数按从小到大打印出来，每个点数后面跟上出现次数

### 要用到的语法点

- **循环里累加**：总和变量要在循环外面先归零，否则每次都被重置
- **字典计数**：先判断键在不在，按需初始化为 0 再加一
- **range 控制次数**：用一个变量控制循环多少轮
- **打印对齐**：想让次数排整齐，可以在格式化时指定宽度，数字就会右对齐

### 做完了自己检查

- [ ] 3 个骰子的总和确实在 3 到 18 之间
- [ ] 重复一千次后，六个点数的次数加起来正好是 1000
- [ ] 每个点数的次数都在 130 到 200 之间（大致均匀但不会完全一样）
- [ ] 把次数改成 10 再跑，会看到次数明显不均匀——这是正常现象，不是 bug

### 卡住看这里

- 总和永远等于最后一次的点数：累加写成了赋值，检查那一行是不是漏了加号
- 字典报 KeyError：先判断键存在再取值，或者用带默认值的取值方法
- 次数加起来不等于 1000：打印时漏掉了某个点数，或者循环次数写错了

### 常见坑

- 把总和变量的初始化写在了循环内部
- 把统计范围写成了 0 到 6，多统计了一个不可能出现的点数

## 关卡 3 · 读懂「2d6+3」这种写法

**建议用时**：45 分钟

### 做出这样就算过

程序接受形如「2d6+3」的输入，理解成：掷 2 个六面骰，把结果加起来再加 3。也支持不带加号的「4d8」和面数为 20 的「1d20+5」。格式不对时给出人话提示，比如「格式应该像 2d6+3」。

### 怎么想（步骤）

1. 先定格式：字母 d 前面是个数，后面是面数，加号后面是固定加值（加值可以没有）
2. 先处理加号：把输入按加号切成两半。如果没有加号，加值就是 0
3. 再处理 d：前半部分按字母 d 切成个数和面数两段，两段都要转成整数
4. 校验：个数和面数都必须是大于 0 的整数，加值可以是 0 或正数
5. 掷骰：循环个数次，每次取一个 1 到面数的随机整数，累加后再加固定加值，最后把「掷出的明细 + 加值 = 总和」打印出来

### 要用到的语法点

- **字符串切分**：按指定字符切成多段，返回的是列表；切割符本身不会出现在结果里
- **转整数与容错**：转换失败会抛异常，用 try / except 接住并提示格式错误
- **条件判断处理可选部分**：先判断有没有加号，再决定走哪条路
- **把解析写成函数**：解析函数输入字符串、返回三个整数；掷骰函数输入三个整数、返回明细和总和。分开之后每部分都能单独测
- **抛出自己的错误提示**：格式不对时打印清楚的说明，比让程序崩溃友好得多

### 做完了自己检查

- [ ] 「2d6+3」的总和落在 5 到 15 之间
- [ ] 「1d20」的总和落在 1 到 20 之间
- [ ] 「2d6」和「2d6+0」结果范围一样
- [ ] 输入「abc」「2d」「d6」都会得到格式提示，不崩
- [ ] 输入「0d6」或「2d0」会被拒绝

### 卡住看这里

- 切分之后列表长度不对：先把你切出来的东西原样打印出来看一眼，比对着结果猜快得多
- 字母 d 的大小写：先把输入统一转成小写再处理，免得同时处理两种写法
- 加号切分后第二个元素是空的：加号后面没写数字，要么当成 0，要么就报格式错误
- 输入里带空格：先去掉两头的空白再解析

### 常见坑

- 把切分结果拿去计算，忘了转成整数
- 只处理了含有加号的情况，导致不带加号时下标越界
- 用面数为 1 的骰子测试不出随机性，验证时至少用 6 面

## 关卡 4 · 随机点名和随机分组

**建议用时**：30 分钟

### 做出这样就算过

程序里放一份名单（十个左右的名字），能做两件事：一是随机抽一个人并打印他的名字，二是给出组数后把名单随机分成几组、每组成员打印出来。分完组所有人出现且只出现一次。

### 怎么想（步骤）

1. 把名单写成一个列表，先写十个名字
2. 随机点名：直接从列表里随机取一个元素打印
3. 随机分组：先把名单复制一份再打乱顺序（别直接打乱原名单，否则下次点名就基于打乱后的顺序了）
4. 按组数切分：算出每组大约几个人，然后循环切片分组；人数除不尽时余数分给前面几组，保证每人都在某一组里
5. 打印每组名单，最后做一次自检：把各组人数加起来，应该等于总人数

### 要用到的语法点

- **random.sample / choice**：一个是不重复地抽若干个，一个只抽一个，按需要选
- **random.shuffle**：原地打乱列表顺序，不返回新列表，所以要先复制
- **列表复制**：直接赋值只是给了同一个列表两个名字，改一个另一个也变；切片或专门的复制方法才是真的复制
- **列表切片**：用下标范围取出一段，注意结尾那一位取不到
- **整除与取余**：整除得到每组基础人数，取余得到要往前面几组多分的人数

### 做完了自己检查

- [ ] 连续点名十次，同一个人偶尔会被重复点到（这是对的，点名是可重复的）
- [ ] 分组结果里，所有人出现且只出现一次
- [ ] 组数大于人数时要么拒绝要么给空组，你选一种并写进提示里
- [ ] 原名单顺序在分组之后没有被改动（再点一次名仍然从完整名单里抽）

### 卡住看这里

- 分组后有人不见了或者有人出现两次：检查切片的下标计算，边界最容易错
- 分组完发现原名单也被打乱了：你打乱的是同一个列表，要先复制
- 每组人数差很多：余数分配的逻辑要写在切分之前

### 常见坑

- 用切片复制时忘了复制，导致两个变量指向同一份数据
- 把人数的整除结果当成每组的固定人数，忽略了余数，最后漏掉几个人
