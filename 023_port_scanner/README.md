# 023 · 端口扫描器（教学版）

> ★★☆☆☆　难度 2.0 / 5　·　021–040 · 联网与窗口
> 3 ~ 4 小时，分 4 次　·　1 个文件（port_scan.py），约 170 行　·　只用 Python 自带功能
>
> **规矩：这份任务卡只给思路和语法点，一行代码都没有。代码由你自己写。**

**一句话**：看看自己电脑上有哪些端口开着、在跑什么服务

## 为什么做它

你电脑上跑着很多你看不见的服务：系统更新、杀毒、你自己起的网页服务……每个占着一个端口。这个项目让你把「自己电脑上开着什么门」看明白，顺便理解一件事：**同一套技术，用在自己机器上是自查，用在别人机器上就是侵入**。所以这一关有一条写死的规矩，代码里必须体现。

## 做完是什么样

程序只扫描 127.0.0.1（你自己的电脑）：可以从 1 扫到 1024，也可以只扫你指定的几个端口；输出哪些端口开着、哪些不开；对开着的端口再读一小段它主动发来的欢迎信息（也就是服务自我介绍），最后出一份报告。约 170 行，一个文件。

## 会练到的语法

`socket 建立连接`　`端口范围循环`　`超时设置`　`多线程`　`线程与函数的配合`　`线程安全的结果收集`　`读服务欢迎信息`　`异常处理`　`耗时统计`　`写报告文件`

> 新东西是「并发」：一个个端口挨着试要几十秒，同时试就快得多。这是你第一次写多线程，也是第一次意识到「等待」是可以重叠的。

## 关卡 1 · 先看一个端口

**建议用时**：20 分钟

### 做出这样就算过

先在电脑上起一个网页服务（用你在 026 会学的方式，或者干脆用一个已知会开着的端口），程序判断指定端口是开着还是关着，输出「端口 135：开着」或「端口 65000：关着」。**程序里必须写死只能测 127.0.0.1。**

### 怎么想（步骤）

1. 新建 port_scan.py，第一件事就是把目标地址写成一个常量，值固定为 127.0.0.1，并在旁边写一行注释说明为什么（自己的电脑随便测，别人的不行）
2. 引入自带的网络功能，建立连接对象，设置一个短超时（1 秒以内，扫描时要试很多次，不能每次都等很久）
3. 用一个「试连」的方法测指定端口：返回 0 表示开着，其他值表示关着或不可达（这个方法不会因为你失败就报错）
4. 打印结果。测试时挑一个你确定关着的端口（比如 65000 这种高位端口）和一个你确定开着的
5. 检查一下：如果把地址改成别的机器，程序会不会照样去扫？想想该怎么阻止这件事

### 要用到的语法点

- **地址写成常量**：放在文件最上面，改起来只有一处；写成 127.0.0.1 表示本机
- **建立连接对象**：要先声明用 TCP 方式连接
- **短超时**：扫描会试上百次，超时设太长整个程序就慢得没法用
- **试连方法**：返回 0 是成功，其他数字是失败原因，不会抛异常
- **用完关闭**：每次试完都要关闭连接对象，否则扫到后面会报「资源不足」

### 做完了自己检查

- [ ] 确定关着的端口报「关着」
- [ ] 确定开着的端口报「开着」
- [ ] 整个测试在几秒内完成（超时没设太长）
- [ ] 扫一百次也不会报资源不足（连接对象关得干净）
- [ ] 文件顶部明确写着 127.0.0.1 和为什么只能是它

### 卡住看这里

- 报错说连接被拒绝：这其实是「端口关着」的正常表现，说明你用的方法不对——换用不会抛异常的那个试连方法
- 扫到一半报资源不足：连接对象没关闭
- 程序很慢：超时设太长了，或者是每次都在等同一个不可达的地址

### 常见坑

- 把目标地址改成别人的 IP 或域名——**这个项目只允许扫自己的电脑**，扫别人是侵入行为，可能违法，也会给你自己惹麻烦
- 不关连接对象，扫几十个端口就崩

## 关卡 2 · 扫一段端口，还要记时间

**建议用时**：30 分钟

### 做出这样就算过

程序从 1 扫到 1024，打印所有开着的端口（一行一个），结尾汇总「1~1024 之间开着 6 个端口，耗时 18.4 秒」。开着的端口如果认识就顺便标一句它一般是干什么的（比如 135、445、3306 各是什么）。

### 怎么想（步骤）

1. 用一个循环遍历端口范围，每个端口调用你上一关写好的判断函数
2. 只把开着的打印出来（关着的太多，全打印会刷屏），顺便计数
3. 准备一张「常见端口 → 服务名」的小表（查一下你电脑上开着的那些端口通常是什么服务），打印时查表标注，查不到就写「未知服务」
4. 记录整个扫描的耗时：开始和结束各取一次时间戳
5. 把扫描函数和打印分开：扫描返回一个「开着的端口列表」，打印是另一段逻辑——下一关要加并发，这个分法能省很多事

### 要用到的语法点

- **端口范围循环**：端口号就是整数，范围循环直接能用
- **字典查表**：常见端口当键、服务名当值，查不到时给默认值
- **只打印结果项**：关着的端口不打印，但计数要算
- **计时**：开头结尾各取一次时间戳，相减得到总耗时
- **函数返回列表**：扫描函数只负责返回结果，打印交给主流程

### 做完了自己检查

- [ ] 扫出来的端口列表跟你用系统命令看到的大致一致（系统命令能看到正在监听的端口）
- [ ] 耗时被正确记录，单位是秒，保留一位小数
- [ ] 常见端口有服务名标注，未知端口显示「未知服务」
- [ ] 只扫本机时总耗时在可接受范围内（一两个超时级别以内）
- [ ] 扫 1 到 200 和扫 1 到 1024 的结果里，前 200 个是一致的

### 卡住看这里

- 太慢了：每个关着的端口都要等到超时，1024 个端口乘上超时时间就很可观——这正是下一关要解决的问题
- 端口列表里有奇怪的项：系统保留端口或临时服务，正常
- 服务名标注总是「未知」：检查查表用的键是什么类型（端口是数字，别拿字符串去查）

### 常见坑

- 把超时设成一秒以上，扫 1024 个端口要等十几分钟
- 把「未知服务」当成错误（其实大部分端口本来就是未知的）

## 关卡 3 · 同时开好几条线：快起来

**建议用时**：40 分钟

### 做出这样就算过

用并发的方式重写扫描：1 到 1024 的扫描耗时降到原来的几分之一（对比一下上一关的时间，写在注释里）；结果跟上一关完全一致；程序里同时开出去的线程数有上限，不是一次开一千个。

### 怎么想（步骤）

1. 先想清楚为什么慢：每个关着的端口都要「等」到超时，而这些等待本来是可以重叠的
2. 引入自带的多线程功能：把「测一个端口」做成一个能交给线程去做的函数，它负责把结果放进一个共享的列表
3. 一次开一批线程（比如每批 100 个），等这批全部结束后再开下一批。用「创建列表 +逐个启动 + 逐个等待结束」的方式控制批次
4. 共享结果列表：多个线程往同一个列表里加东西时，用加锁的方式保护一下，或者用线程安全的队列（用哪个都行，但要能说出为什么需要保护）
5. 对比测试：把两版的耗时都记下来。如果并发版本没有明显变快，检查是不是并发写错了（比如你其实还是在等每个线程结束才开下一个）

### 要用到的语法点

- **多线程**：把要做的事包成一个函数，交给线程对象去跑
- **启动与等待**：启动线程只是「让它开始跑」，还要用一个方法等它结束，否则程序可能提前退出
- **分批控制数量**：一次只开固定数量的线程，跑完一批再开下一批，避免把电脑拖垮
- **共享结果的保护**：多个线程同时改一个列表可能互相覆盖，用锁或者线程安全的队列
- **对比耗时**：想验证优化有效，就两版都跑一次，把数字摆在一起

### 做完了自己检查

- [ ] 并发版本的结果跟逐端口版本完全一致（开着的端口一个不多一个不少）
- [ ] 耗时有明显下降（一般能快好几倍）
- [ ] 同时开的线程数不超过你设定的上限
- [ ] 连跑三次结果稳定，不会偶尔少几个端口
- [ ] 线程全部结束后程序正常退出（没有卡住不结束的情况）

### 卡住看这里

- 结果偶尔少几个：共享列表被并发写坏了，加锁或者换成线程安全的容器
- 没有变快：你可能在循环里对每个线程都立刻等待结束，那就等于没并发
- 程序卡住不退出：有线程没被等待，或者线程里有死循环

### 常见坑

- 一次开一千个线程（电脑会卡，而且很多系统顶不住）
- 以为并发一定更快：这里快是因为「等待」重叠了，如果是纯计算任务，多线程反而可能更慢

## 关卡 4 · 读服务自我介绍，出一份报告

**建议用时**：35 分钟

### 做出这样就算过

对每个开着的端口，程序尝试连接并读一小段对方主动发来的文字（有的服务一连上就会自我介绍，比如版本号），把读到的内容记录下来（可能读不到，读不到就写「没有问候信息」）；最后输出一份报告并写进文件：扫描范围、耗时、开着的端口列表、每个端口的服务名和问候信息。

### 怎么想（步骤）

1. 读问候信息：连上之后不马上关闭，而是给对方一点时间，读一小段数据（设一个读超时，别等太久）；读不到就当作没有
2. 读到的内容可能不是文字（是二进制），要处理解码失败的情况——接住异常，显示成「二进制数据，长度 N」
3. 把结果整理成表：端口、服务名、问候信息（截断到一行）
4. 报告写文件：带上扫描时间、范围、耗时、结果表；同时打印到屏幕一份
5. 最后再自我检查一遍安全边界：代码里除了 127.0.0.1，有没有任何地方能让你改成别的地址？如果没有，就在报告开头写一句「本工具只扫描本机」

### 要用到的语法点

- **接收数据**：连接成功后可以用接收方法拿对方发来的内容，给一个缓冲区大小
- **读超时**：给连接对象设置超时，避免读不到内容时死等
- **解码失败处理**：二进制内容按文字解码会失败，接住异常改成描述性文字
- **截断单行显示**：问候信息里的换行符会让表格错位，先替换成空格再截断
- **写报告**：把报告攒成几行文字，打印一份、写文件一份

### 做完了自己检查

- [ ] 开着的端口都能拿到服务名（认识的）或者「未知服务」
- [ ] 有的端口能读到问候信息，有的读不到——两种情况都正常显示
- [ ] 报告文件里内容完整，中文不乱码
- [ ] 报告开头有扫描时间和「本工具只扫描本机」的说明
- [ ] 全程没有任何一次连接到了 127.0.0.1 以外的地址

### 卡住看这里

- 读问候信息时卡住：没设读超时，对方什么都没发你就一直等
- 全是乱码：对方发的是二进制，接住解码异常改成描述就行
- 报告里表格错位：问候信息里的换行破坏了排版，先清理换行

### 常见坑

- 为了让结果好看，把超时设得很长（扫描会慢到无法接受）
- 把读到的问候信息当命令执行（对方发来的内容永远只是「文字」，绝不执行）
