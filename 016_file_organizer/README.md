# 016 · 文件自动分类整理器

> ★½☆☆☆　难度 1.5 / 5　·　001–020 · 找回手感
> 3 小时左右，分 4 次　·　1 个文件（file_organizer.py）+ 一个自动生成的日志文件，约 170 行　·　只用 Python 自带功能
>
> **规矩：这份任务卡只给思路和语法点，一行代码都没有。代码由你自己写。**

**一句话**：把一堆乱文件按类型或日期自动归类到子文件夹

## 为什么做它

下载文件夹里堆着几十个文件，图片、文档、压缩包混在一起，想找昨天那份作业要翻半天。这个项目让程序替你把它们归位——它的重点和 013 一样，是**规则要能改、操作要能撤**。整理文件是你以后每天都能用上的一个程序。

## 做完是什么样

程序先打印一张整理计划：哪个文件会被移到哪个文件夹，一共几项；确认之后才真的移动。分类规则写在一个表格里（图片放「图片」、文档放「文档」……），还能按年月归档；重名文件会自动加序号不会覆盖；每次整理都写日志，支持一键撤销。约 170 行，一个文件。

## 会练到的语法

`字典配置规则`　`字符串取扩展名并转小写`　`创建文件夹`　`移动文件`　`重名检测与自动编号`　`按时间格式化文件夹名`　`列表收集计划`　`日志追加写入`　`逆向操作（撤销）`　`输入确认`

> 新东西是「用一张表驱动程序行为」：分类规则不写死在代码里，而是放在字典里，以后想加一类只改表，不改逻辑。

## 关卡 1 · 先出一张整理计划，别动手

**建议用时**：25 分钟

### 做出这样就算过

给一个装满杂物的测试文件夹，程序打印一张计划表：每行是「文件名 → 目标文件夹名」，最后汇总「共 12 个文件，将分成 4 类」。这一步一个文件都不许动。

### 怎么想（步骤）

1. 新建 file_organizer.py，然后建一个测试文件夹：随手放十几张图、几个文本、几个压缩包，故意混在一起
2. 先写一张分类表：扩展名对应分类名。先定四类就够——图片、文档、压缩包、其它
3. 遍历文件夹里的文件，取扩展名（转成小写，免得 JPG 和 jpg 被当成两类）
4. 拿扩展名去表里查分类名；查不到就归到「其它」
5. 把「文件 → 分类」存成列表，最后统一打印成计划表，并统计有几个分类

### 要用到的语法点

- **字典当配置表**：键是扩展名（带点），值是分类文件夹名；想加一类就往字典里加一行
- **取扩展名并统一大小写**：路径对象能直接给你后缀，记得转成小写再查表
- **查表带默认值**：字典取值时可以指定「查不到就用这个」，省掉一次判断
- **列表收集计划**：先把所有「怎么移」攒成列表，打印出来给人看，还没开始移
- **统计分类数**：把分类名放进集合，集合会自动去掉重复

### 做完了自己检查

- [ ] 每个文件都有归属，没有漏掉的
- [ ] 大小写扩展名被归成同一类（.JPG 和 .jpg 都进图片）
- [ ] 没有分类的文件进了「其它」而不是被忽略
- [ ] 跑完之后去文件夹里看：一个文件都没动
- [ ] 汇总数字和计划表行数一致

### 卡住看这里

- 取到的扩展名带着大写：查表前先统一转小写
- 有的文件没出现在计划里：检查是不是把没有扩展名的文件漏了（它们也应该进「其它」）
- 分类数是错的：统计时用了列表长度而不是去重后的数量

### 常见坑

- 直接拿真实文件夹测试（先建测试文件夹，这是第三次强调了）
- 把文件夹也当成文件计划进去

## 关卡 2 · 真的动手，把文件移进去

**建议用时**：30 分钟

### 做出这样就算过

程序打印计划后询问确认，确认后按计划建子文件夹并移动文件，每移一个打印一行进度，结束后汇总「成功 12 个，跳过 0 个」。拒绝确认时一个文件都不动。

### 怎么想（步骤）

1. 加一个确认环节：把用户输入去掉空白、转成小写，只有明确的肯定才继续
2. 按计划逐项处理：先算出目标文件夹路径（原来文件夹加上分类名），如果这个文件夹不存在就先建出来
3. 移动文件用自带功能；移动之前先确认目标文件夹已经建好，否则会失败
4. 每移一个就打印一行，方便你盯着看有没有异常
5. 统计成功和跳过（失败）的数量，全部结束后汇总打印

### 要用到的语法点

- **创建文件夹**：建目录时允许「已经存在就当作成功」，这样重复运行也不会报错
- **拼接目标路径**：原文件夹路径加上分类名，就是目标文件夹
- **移动**：自带功能可以在同一个磁盘内快速移动；目标文件夹必须存在
- **二次确认**：用户输入统一处理后只认明确的肯定
- **异常逐项处理**：单个文件失败不应该让整个程序停下，接住异常记下来继续

### 做完了自己检查

- [ ] 确认后文件真的进了对应的子文件夹
- [ ] 拒绝确认时文件夹里一个变化都没有
- [ ] 同一批文件再跑一次：因为它们已经在子文件夹里，第二层不会再被整理（要保证不递归乱翻）
- [ ] 失败的文件会被汇报出来，不是静默跳过
- [ ] 新建的文件夹名字跟分类表里写的一致

### 卡住看这里

- 移动报错说找不到目标目录：先建目录再移动，顺序别反
- 第二次运行把子文件夹里的文件又移了一遍：扫描时要跳过文件夹，只处理当前这一层的文件
- 计划里明明有 12 个，实际只移了 11 个：有一个失败了但你没记录

### 常见坑

- 递归扫描整个文件夹（那样会把自己刚建好的分类文件夹也翻一遍）
- 移动失败时用了「跳过」却根本没记原因，出问题查不出来

## 关卡 3 · 规则变成表，再加按年月归档

**建议用时**：35 分钟

### 做出这样就算过

程序支持两种整理方式：1 按类型（图片/文档/压缩包/其它） 2 按年月（2026-10 这样的文件夹）。分类表要能一眼看懂、加一行就多一类；文档类再细分出一层（比如「文档/表格」「文档/演示」）。

### 怎么想（步骤）

1. 把分类表重新组织一下：让「扩展名 → 分类路径」支持多级（分类名里带斜杠就表示子文件夹）
2. 把「按年月」做成另一种规则：取文件的修改时间，格式化成「年-月」当文件夹名
3. 把两种规则都写成「输入一个文件、输出目标文件夹名」的函数，主流程根据选择调用不同的那个
4. 加一条规则开关：某些扩展名可以指定「不整理」（比如正在用的临时文件）
5. 把分类表打印出来给用户看一遍，让程序自己说明它打算怎么分

### 要用到的语法点

- **多级文件夹路径**：分类名写成带斜杠的形式，建目录时它会一次把多层都建出来
- **取修改时间**：路径对象上的 stat 里有修改时间戳，能转成日期对象再格式化
- **格式化成年月**：日期格式化时指定年和月，就是 2026-10 这种
- **把规则做成函数**：两个规则各是一个函数，输入文件、输出目标文件夹名，主流程只负责选
- **不整理名单**：把不想动的扩展名放一个集合，遇到就跳过

### 做完了自己检查

- [ ] 按类型整理时，文档类里确实出现了子文件夹
- [ ] 按年月整理时，文件夹名跟文件的修改时间对得上
- [ ] 分类表里加一类（比如音频），不用改其它代码就能生效
- [ ] 不整理名单里的文件留在原地
- [ ] 两种方式各跑一次，都能先打印计划再执行

### 卡住看这里

- 子文件夹没被建出来：建目录时没开启「多层一起建」的选项
- 年月显示成时间戳数字：忘了把时间戳转换成日期对象
- 加了一类但没生效：新类的扩展名写进字典了吗，扩展名前的点写了吗

### 常见坑

- 年月文件夹用文件的创建时间（不同系统行为不一致），用修改时间更可靠
- 分类名里用了系统不允许的字符（斜杠只用来表示层级，别用在名字中间）

## 关卡 4 · 重名不覆盖、写日志、能撤销

**建议用时**：35 分钟

### 做出这样就算过

整理时碰到重名文件自动加序号（照片.jpg 已存在就变成 照片_2.jpg），绝不覆盖；每次整理把「从哪移到哪」写进日志；程序菜单里有「撤销上次整理」，撤销后所有文件回到原位、文件夹结构跟整理前一致。

### 怎么想（步骤）

1. 重名处理：移动前检查目标路径是否已存在，存在就在主文件名后面加下划线加序号，一直试到不冲突为止
2. 日志格式：每行「原路径 目标路径」，用文件名里不会出现的符号当分隔符，追加写入
3. 撤销：从日志里读出全部记录，倒着做一遍（把目标移回原路径），做完之后删掉空的分类文件夹
4. 撤销也要处理冲突：如果原位置已经有同名文件，也要加序号或者提示
5. 删空文件夹：判断文件夹里还有没有内容，空了就删掉，让撤销结果更干净

### 要用到的语法点

- **重名自动编号**：拿目标路径去问「存在吗」，存在就换个序号再问，用一个循环试到不冲突
- **主文件名与扩展名分开处理**：序号要插在扩展名前面，不能加在最后
- **日志追加**：追加模式写入，每行一条；指定编码
- **倒序撤销**：撤销要和整理顺序相反，避免中间状态互相撞车
- **删除空文件夹**：判断文件夹里是否为空，空了再删；删除文件夹和删除文件是两回事

### 做完了自己检查

- [ ] 目标位置已有同名文件时，新文件被改成「名字_2」而不是覆盖
- [ ] 序号规则在连续三个重名时能给出 _2、_3
- [ ] 撤销之后文件夹结构恢复成整理前的样子（分类文件夹消失，文件回原位）
- [ ] 日志文件里每行都能被正确解析回两个路径
- [ ] 日志不存在时撤销功能给提示不崩

### 卡住看这里

- 序号加在了扩展名后面（照片.jpg_2）：要把主文件名和扩展名拆开，序号插在中间
- 撤销后有空文件夹留着：撤销完要检查并删掉空目录
- 撤销时文件乱跑：多半是正序撤销，改成倒序

### 常见坑

- 用移动加覆盖的方式处理重名（会静默丢掉一个文件，最危险的 bug）
- 日志写得含糊（只记了文件名没记路径），撤销时找不到文件
