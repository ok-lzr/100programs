【一、项目背景与目标】

一篇超过两百行的 Markdown 笔记或技术文档，如果没有目录，读者只能靠滚动条找章节；
而手工维护目录更痛苦：加了一节就要重排编号，删掉一节就要重新检查所有链接，
标题改了锚点又全部失效。用编辑器插件又常常绑死某个平台，换到另一个渲染器后锚点规则不同，
链接全部点不动。

本项目实现一个纯命令行的 Markdown 目录生成器：扫描文档中的标题层级，
生成带锚点链接的多级目录，并支持"就地更新"——文档里只要预留下开始与结束标记，
同一条命令就能把目录刷新到最新状态，还能用 --check 在提交前验证目录是否需要更新。

目标用户是写技术笔记与项目文档的开发者、维护知识库文档的团队成员，
以及需要批量给一批 Markdown 文件补目录的人。工具只处理文本文件，
会跳过二进制文件与非 Markdown 文件；就地改写默认关闭，开启后必须先备份。

【二、功能需求清单】

1. 核心功能
   1.1 标题识别：识别行首 1 到 6 个井号加至少一个空格（或制表符）的标题行；
       井号后面没有空格（如 #标题）不算标题，可由 --lenient 放宽。
       可选 --setext 识别下划线形式的标题（文本行下方为等号或连字符）。 
   1.2 代码块忽略：由三个反引号或三个及以上波浪号开始的围栏代码块内部的所有井号行
       一律不视为标题；围栏需要语言标记时按原样保留；围栏内出现嵌套同种围栏的行按标准规则处理。
       同时忽略 HTML 注释块内的内容（由小于感叹号双减号开始、双减号大于号结束）。
   1.3 行内内容清理：提取标题文本时去掉行内代码的反引号、加粗与斜体的星号与下划线、
       图片语法（保留 alt 文字）、纯链接语法（保留链接文字），保证目录中显示干净文本。
   1.4 锚点生成：默认使用 GitHub 风格——标题文本转小写、去掉标点与符号、
       空格替换为连字符、保留中日韩文字与数字、连续连字符压缩为一个、
       同名标题按出现顺序追加 -1、-2；--anchor-style github/gitlab/none 可切换，
       none 时只输出标题文本不生成链接。
   1.5 层级与深度：--max-depth N（默认 6）限制目录层级；--min-depth N 可忽略一级标题
       （常用于文档标题本身就是一级标题、不希望出现在目录里的场景）。
   1.6 层级归一化：--normalize 把出现跳跃的层级（例如一级标题后直接三级标题）
       压缩为连续层级，避免生成非法缩进；默认不归一化但在标准错误流给出提示。
   1.7 列表样式：--bullet "-"（默认）、"*"、"+" 或 "1."（有序列表）；
       --indent 2 或 4 控制每级缩进空格数。
   1.8 目录插入与更新：--insert 在第一个标题之前插入目录；
       --update 在文档中查找起始标记与结束标记（默认分别为 "<!-- TOC -->"
       与 "<!-- /TOC -->"，可用 --marker-start 与 --marker-end 自定义），
       只替换两标记之间的内容；找不到标记时若同时给出 --insert 则改为插入。
   1.9 校验模式：--check 只检查目录是否为最新，不写任何文件；
       目录过期时输出差异行并返回退出码 1（可直接用于持续集成的检查步骤）。
   1.10 批量处理：--glob "docs/**/*.md" 对匹配文件逐个处理，--exclude 排除 node_modules、
       .git、build 等目录；每个文件的处理结果单独输出一行。

2. 输入与交互
   2.1 位置参数为待处理文件或目录；目录自动递归查找扩展名为 .md、.markdown、.mdown 的文件。
   2.2 默认把生成的目录打印到标准输出，不改动原文件；
       --output FILE 写新文件；--in-place 原地改写需同时加 --apply 与 --force。
   2.3 --dry-run 为默认行为，--in-place 时若未加 --apply，只打印将要写入的内容摘要
       （新增行数、删除行数、首尾各 3 行上下文）。
   2.4 --encoding 强制输入编码；默认按 BOM 识别 utf-8-sig 与 utf-16，
       无 BOM 时依次尝试 utf-8 与 gb18030，失败的文件记为跳过而不是中断。
   2.5 --keep-newline 保留原文件的换行风格（CRLF 与 LF）与是否存在末尾换行；
       默认开启，写入时如果检测到混合换行则以出现次数多的一种为准并给出提示。

3. 输出与展示
   3.1 标准输出只写目录文本；统计信息（扫描文件数、标题数、最大层级、跳过文件数）
       写标准错误流。
   3.2 目录文本默认不带外层列表标题；--title "目录" 可在目录前插入一行普通文本标题
       （该行不是 Markdown 标题，不会进入目录自身）。
   3.3 --json 输出结构化结果：每个文件的标题列表（层级、文本、锚点、行号）与目录文本。
   3.4 --toc-only 只输出目录正文，便于重定向到单独文件。

4. 异常与边界处理
   4.1 输入文件不存在或不可读时报错并计入失败，批量模式下继续处理其它文件，最终退出码为 2。
   4.2 二进制文件保护：读取时若检测到 NUL 字节，或扩展名不在允许列表中，
       直接跳过并输出"跳过（非文本文件）"。
   4.3 空文档或没有任何标题时输出提示"未找到标题"并返回退出码 0，不生成空目录。
   4.4 文档中只有一个标题时默认仍生成一行目录，可用 --min-headings 2 抑制。
   4.5 围栏代码块未闭合时按"一直到文件结尾都是代码块"处理并在标准错误流给出警告。
   4.6 起始标记与结束标记不配对（只有开始没有结束、或结束在开始之前）时报错并退出码 2，
       不做任何写入。
   4.7 --in-place 写入前生成原文件名加 .bak_YYYYMMDD_HHMMSS 的备份，
       写入采用临时文件加 os.replace 的原子替换；写入失败时保留备份并提示恢复方法。
   4.8 标题层级跳跃且未开启 --normalize 时输出警告但照常生成目录。

【三、技术要求与约束】

1. 语言与版本：Python 3.10 及以上。
2. 允许使用的库：仅使用标准库 argparse、re、sys、os、json、time、logging、pathlib、
   unicodedata、dataclasses、typing、glob、shutil、difflib、hashlib；
   禁止使用 markdown、mistune、markdown-it-py、beautifulsoup4 等第三方库。
3. 禁止事项：禁止在文本内部做不区分上下文的全局替换（目录更新必须严格限定在标记区间内）；
   禁止改动标题行本身的内容（只读不写）；禁止在未加 --apply 与 --force 时写入原文件；
   禁止把 CRLF 文件改写为 LF 而不提示。
4. 代码组织：至少拆分为 scanner.py（逐行状态机识别标题与代码块）、anchor.py（锚点生成与去重）、
   render.py（列表渲染）、updater.py（标记区间查找与替换）、cli.py（参数与批量调度）。
   scanner 必须是逐行状态机并返回带行号的标题列表，禁止使用正则对整个文档做一次性匹配。
5. 编码规范：类型注解与 docstring 齐全；状态机使用枚举表示状态（normal、fenced_code、
   html_comment、front_matter）；锚点函数写清保留与替换的字符集合。
6. 正确性约束：生成的锚点必须与主流渲染器一致，自测用例需覆盖中文标题、含标点标题、
   同名标题、含行内代码标题、Emoji 标题五类；目录自身不能出现在目录中。

【四、设计要点】

1. 数据结构
   1.1 Heading：字段 level（int）、text（清理后的显示文本）、raw_text（原始行内容）、
       line_no（int）、anchor（str）、duplicate_index（int）。
   1.2 TocOptions：字段 max_depth、min_depth、bullet、indent、anchor_style、
       normalize、title、setext、lenient。
   1.3 UpdateRegion：字段 start_line、end_line、found（bool）；用于定位标记区间。
   1.4 FileReport：字段 path、headings、toc_text、changed、added_lines、removed_lines、
       skipped_reason。
   1.5 锚点去重表：dict[str, int]，记录基础锚点已被使用的次数。

2. 关键算法或流程
   2.1 逐行状态机：维护状态与围栏字符；遇到以三个反引号或三个波浪号开头且去掉缩进后
       与当前围栏匹配的行则切换状态；仅在 normal 状态下用正则匹配标题；
       同时记录 front matter（文件开头由三个连字符包围的 YAML 块）并跳过。
   2.2 标题正则：^ {0,3}(#{1,6})([ \t]+)(.+?)[ \t]*#*[ \t]*$，
       要求井号后有空白；--lenient 时把空白改为可选。
   2.3 文本清理顺序：先剥离行内代码反引号，再删除成对的星号与下划线标记，
       再把图片语法替换为 alt 文本，最后把链接语法替换为链接文字，再去掉首尾空白。
   2.4 锚点生成：对清理后文本先做 Unicode NFKC 归一化，转小写，
       删除不在"字母、数字、连字符、下划线、空格、中日韩字符"集合内的字符，
       空格转连字符，压缩连续连字符，最后按去重表追加序号。
   2.5 层级归一化：扫描标题序列，若当前层级大于前一个标题层级加一，则把当前层级
       与前一个层级加一之间的差值向下平移；实现方式为维护一个映射表。
   2.6 更新流程：定位开始标记行与结束标记行（保留标记行本身），
       把两行之间的内容替换为新生成的目录，其余行原样保留；
       行尾换行风格按检测结果统一处理；比较新旧内容是否一致以决定 changed 标志。
   2.7 校验模式：生成新目录后与原目录逐行比较，使用 difflib.unified_diff 输出前 20 行差异。

3. 接口或命令设计
   3.1 python markdown_toc.py README.md
   3.2 python markdown_toc.py docs/ --glob "**/*.md" --max-depth 3 --bullet "-" --indent 2
   3.3 python markdown_toc.py notes.md --update --in-place --apply --force
   3.4 python markdown_toc.py docs/ --check --json
   3.5 核心函数签名：scan_headings(lines: list[str], opts: TocOptions) -> list[Heading]；
       make_anchor(text: str, used: dict[str, int], style: str) -> str；
       render_toc(headings: list[Heading], opts: TocOptions) -> str；
       update_region(lines: list[str], toc: str, start: str, end: str) -> list[str]。

【五、运行方式与示例】

1. 安装与运行：无需安装依赖，执行 python markdown_toc.py --help 查看全部参数。
2. 示例一（打印目录）：
   输入：python markdown_toc.py 使用说明.md --max-depth 2
   输出：- [一、安装](#一安装)
           - [1. Windows](#1-windows)
         - [二、快速开始](#二快速开始)
         （stderr）共 3 个标题，最大层级 2，耗时 0.01 s
3. 示例二（就地更新）：
   输入：python markdown_toc.py 使用说明.md --update --in-place --apply --force
   输出：已更新 使用说明.md（新增 4 行，删除 3 行），备份 使用说明.md.bak_20240301_101500
4. 示例三（校验目录是否过期，用于提交前检查）：
   输入：python markdown_toc.py docs/ --check
   输出（stderr）：docs/guide.md 目录已过期（差异 5 行），退出码 1
5. 示例四（忽略代码块内的井号行）：
   输入：文档中围栏代码块内含有以井号开头的注释行，执行 python markdown_toc.py sample.md
   输出：该注释行未出现在目录中，标题数与实际标题数一致
6. 示例五（跳过二进制文件）：
   输入：python markdown_toc.py docs/
   输出（stderr）：跳过 docs/logo.png（非文本文件），继续处理其余 12 个文件
7. 示例六（标记不配对）：
   输入：python markdown_toc.py broken.md --update
   输出（stderr）：错误：找到起始标记但未找到结束标记，未做任何写入，退出码 2

【六、验收标准】

[ ] 1. 五级标题文档生成的目录缩进层级与 --indent 设置一致，列表符号与 --bullet 一致。
[ ] 2. 围栏代码块内以井号开头的行不被识别为标题，代码块结束后的标题正常识别。
[ ] 3. HTML 注释块内的伪标题行被忽略。
[ ] 4. 标题中的行内代码反引号、加粗星号被正确剥离，目录文本干净。
[ ] 5. 中文标题生成的锚点可被 GitHub 页面正确跳转（手工点击验证）。
[ ] 6. 两个同名标题的锚点分别为 name 与 name-1，链接均可用。
[ ] 7. --max-depth 2 时三级及以下标题不出现在目录中。
[ ] 8. --update 只替换两个标记之间的内容，文档其它部分逐字节不变（用哈希比对验证）。
[ ] 9. --check 在目录最新时返回退出码 0，过期时返回 1，且不修改任何文件。
[ ] 10. --in-place 未加 --force 或 --apply 时不写入文件。
[ ] 11. --in-place 加 --force 后生成 .bak 备份，新文件可正常渲染且目录链接可用。
[ ] 12. CRLF 文件处理后仍为 CRLF，末尾换行状态保持原样。
[ ] 13. 含 NUL 字节的文件被跳过且不抛 UnicodeDecodeError。
[ ] 14. 没有任何标题的文档输出提示并返回退出码 0。
[ ] 15. 批量处理 50 个文件时，每个文件的结果单独成行，跳过数统计正确。

【七、可选扩展】

1. 增加 --numbering 为标题自动加序号（2.1、2.1.1），并同步写回标题行（需备份与确认）。
2. 增加 --check-links 校验目录中所有锚点在文档中确实存在，报告失效链接。
3. 增加 --sidebar 输出适合文档站点的侧边栏结构（不含文档正文）。
4. 增加 --watch 监听文件变化自动刷新目录，配合编辑器实时预览。
5. 增加 --stats 输出标题层级分布直方图与最长标题、最深章节路径。

【八、涉及知识点】

- Markdown 语法要点：ATX 标题、Setext 标题、围栏代码块、HTML 注释、front matter
- 逐行状态机设计（避免用正则一次性处理整个文档）
- 正则表达式的锚定、非贪婪匹配与字符类
- 锚点生成规则与多语言字符处理、unicodedata NFKC 归一化
- 列表渲染的缩进规则与有序列表编号
- 标记区间内的精准替换与逐字节不变性验证
- 换行风格（CRLF 与 LF）检测与保留
- 编码探测、BOM 处理与二进制文件判定
- 备份、原子写入与 dry-run 默认的工程习惯
- 用退出码表达"检查未通过"以便接入持续集成
