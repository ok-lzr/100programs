【一、项目背景与目标】

工作中经常需要算几个并不复杂、但每次都要临时想的日期问题：项目从今天起 30 个工作日之后
是哪一天；两个日期之间除去周末和法定节假日还剩多少个工作日；签证到期日是不是落在周末；
某个纪念日距离今天还有几天；给定的年份一共有多少个工作日。用手机日历手动数既慢又容易错，
而在网上搜到的在线工具通常无法排除自定义的公司假期。

本项目提供一个纯命令行、完全离线的日期计算器。节假日不联网抓取，而是由用户维护一份
JSON 假期表，这样可以同时表达法定节假日与公司内部假期、调休补班等特殊情况。
目标用户是需要排期与倒计时的普通办公人群，以及想把日期逻辑写对的学习者。

做完成品后，你可以用它：算出"今天加 45 个工作日"的准确日期；统计 2024 年全年工作日总数；
查看距离下一个节假日还有多少个工作日；把一批截止日期批量换算成工作日剩余天数；
查询任意日期是当年的第几天、第几周、星期几。

工具不依赖任何第三方库，只用 datetime 与 calendar 模块；这一点是本项目的硬性训练目标——
把标准库的日期能力用透，理解 ISO 周、闰年、跨年周等容易出错的地方。

【二、功能需求清单】

1. 核心功能
   1.1 日期差值：给定两个日期，输出自然日差、工作日差（默认排除周六周日与假期表内日期）、
       完整周数与剩余天数；结果同时给出符号方向（A 比 B 晚 / 早）。
   1.2 工作日推算：给定基准日期与偏移量，求偏移 N 个工作日后的日期，N 可为负数（向前推）；
       偏移过程逐日推进，跳过所有非工作日，并在 --verbose 时列出被跳过的日期及原因。
   1.3 年份统计：--year 2024 输出该年总天数、周末天数、假期天数、工作日天数、
       以及每个月的天数与工作日数（含闰年 2 月 29 日的处理）。
   1.4 周信息查询：输出 ISO 周序号（isocalendar）、年内第几天、年内第几周（分别按
       %U 与 %W 两种口径）、该周的起止日期（默认周一至周日）。
   1.5 节日倒计时：读取假期表，计算距离下一个节日还有多少自然日与工作日；
       --all 列出未来 12 个月内所有节日及其倒计时，按日期升序排列。
   1.6 纪念日推算：--anniversary 1000 计算从某日期起第 1000 天、第 10000 天对应的日期，
       用于生日、入职纪念日等场景。
   1.7 批量模式：--file dates.txt 逐行读取日期对，按分隔符（默认逗号或制表符）拆分，
       输出每行的计算结果并汇总；空行与以井号开头的注释行跳过。
   1.8 日期解析：支持 2024-03-01、2024/03/01、20240301、2024.03.01 四种写法，
       以及相对关键字 today、tomorrow、yesterday，和 +3d、-1w、+2m 形式的相对表达式。

2. 输入与交互
   2.1 两种主要调用形式：位置参数 "DATE1 DATE2"（差值模式）与 "--from DATE --add-days/-add-workdays N"。
   2.2 --holidays holidays.json 指定假期表；未指定时使用内置的空假期表并提示"未加载假期表"。
   2.3 --workweek 指定工作日，默认 1,2,3,4,5（周一至周五），可写成 0,1,2,3,4 等其它组合。
   2.4 --include-weekend 反转语义，把周末也算作工作日，只排除假期表内的日期。
   2.5 默认以本机当前日期为 today 的取值，--today 2024-03-01 可覆盖，便于测试复现。

3. 输出与展示
   3.1 默认中文文本输出，每个指标一行，日期统一格式化为 YYYY-MM-DD，星期用中文（星期一）。
   3.2 --json 输出结构化结果，字段固定为 start、end、days、workdays、weekends、holidays、
       weeks、remainder_days、sign，便于脚本消费。
   3.3 --iso 输出 ISO 8601 日期字符串，供跨系统对接。
   3.4 --verbose 在推算工作日时额外打印逐日明细，格式为 "2024-03-02 星期六 跳过（周末）"。
   3.5 结果写标准输出，警告与错误写标准错误，保证重定向与管道安全。

4. 异常与边界处理
   4.1 日期格式非法（2024-02-30、2024-13-01、2024-2-3）时报错到 stderr 并给出"期望格式"提示，
       退出码 2。
   4.2 两个日期顺序颠倒时自动交换并提示"已自动按时间先后排序"，结果符号取负。
   4.3 假期表文件缺失、不是合法 JSON、或字段类型错误时，给出具体行号与原因，退出码 2。
   4.4 假期表中出现 2024-02-30 这类非法日期时跳过该条并累计警告，不中断整体计算。
   4.5 日期超出 datetime.date 支持的 1 年 1 月 1 日到 9999 年 12 月 31 日范围时报错。
   4.6 工作日偏移量导致结果超出可表示范围时，报错并提示缩小偏移量，退出码 3。
   4.7 当 --workweek 被设置为空（七天全是休息日）时立即参数校验失败，避免死循环。

【三、技术要求与约束】

1. 语言与版本：Python 3.10 及以上。
2. 允许使用的库：仅使用标准库 argparse、datetime、calendar、json、re、sys、logging、
   dataclasses、typing、pathlib、functools、itertools；禁止使用 dateutil、arrow、pandas、
   holidays 等第三方库，禁止发起任何网络请求。
3. 禁止事项：禁止用字符串比较代替日期比较（必须先解析为 datetime.date）；禁止自己实现
   闰年判断（使用 calendar.isleap）；禁止在循环里无上限地逐日推进（工作日推算必须设置
   迭代上限，例如 100000 天，超过即报错）。
4. 代码组织：至少拆分为 parser.py（日期与相对表达式解析）、calendar_utils.py
   （HolidayCalendar 类与工作日逻辑）、report.py（文本与 JSON 格式化）、cli.py（参数入口）；
   日期解析与业务计算必须分离，便于单独测试。
5. 编码规范：公开函数带类型注解与 docstring，写明日期的合法取值范围；模块级使用
   logging；不使用全局可变状态保存假期表，全部通过参数或类实例传递。
6. 正确性约束：所有涉及"周"的计算必须明确口径（ISO 8601 周以周一为一天）；
   文档与代码注释中必须写清跨年周的归属规则（例如 2021-01-01 属于 2020 年第 53 周）。

【四、设计要点】

1. 数据结构
   1.1 HolidayCalendar：字段 holidays（set[date]）、workweek（frozenset[int]，0 为周一）、
       name_map（dict[date, str] 保存节日名称）；提供 is_workday(d)、next_workday(d)、
       prev_workday(d)、add_workdays(d, n)。
   1.2 DateDiff：字段 start、end、days、workdays、weekends、holiday_count、weeks、
       remainder_days、sign。
   1.3 WeekInfo：字段 date、iso_year、iso_week、iso_weekday、day_of_year、week_u、
       week_w、week_start、week_end。
   1.4 假期表 JSON 结构：{"holidays": [{"date": "2024-10-01", "name": "国庆节"},
       {"date": "2024-10-02", "name": "国庆节"}], "workdays": ["2024-09-29"]}，
       其中 workdays 表示调休上班日，优先级高于周末规则。

2. 关键算法或流程
   2.1 工作日差统计：先交换保证 start <= end；逐日迭代 start 到 end（含左端不含右端或两端
       都含，需在文档中明确并写成参数 --inclusive），对每一天判断是否为工作日；工作日判断
       顺序为：先查调休上班日表（是则算工作日），再查假期表（是则不算），再看是否落在
       workweek 内。单次迭代超过 100000 天时走快速估算并给出近似标记。
   2.2 工作日推算：当 n >= 0 时，循环 n 次调用 next_workday；当 n < 0 时循环 |n| 次调用
       prev_workday；--verbose 时收集每次跳过的日期与跳过原因，统一在结果后输出。
   2.3 日期解析：先用 re 匹配四种格式并归一化为 YYYY-MM-DD，再用
       datetime.date.fromisoformat 解析；相对关键字与 +3d/-1w/+2m 表达式在解析阶段展开为
       绝对日期，展开时依赖注入的 today 值，保证测试可复现。
   2.4 节日倒计时：把假期表按日期分组为"节日区间"（同名且连续的日期合并为一个节日），
       过滤掉已经结束的区间，取最近一个，分别计算自然日差与工作日差。
   2.5 年份统计：遍历 1 到 12 月，用 calendar.monthrange 取每月天数与首日星期，
       逐月累计周末天数与工作日天数，再扣除落在该月的假期表日期。

3. 接口或命令设计
   3.1 python date_calculator.py 2024-01-01 2024-12-31 --holidays holidays.json
   3.2 python date_calculator.py --from today --add-workdays 45 --verbose
   3.3 python date_calculator.py --year 2024 --json
   3.4 python date_calculator.py --from 2024-03-01 --anniversary 10000
   3.5 核心函数签名：parse_date(text: str, today: date) -> date；
       workday_diff(a: date, b: date, cal: HolidayCalendar) -> DateDiff；
       add_workdays(d: date, n: int, cal: HolidayCalendar) -> date。

【五、运行方式与示例】

1. 安装与运行：无需安装依赖，准备一份 holidays.json 后执行 python date_calculator.py --help。
2. 示例一（自然日与工作日差值）：
   输入：python date_calculator.py 2024-01-01 2024-01-31 --holidays holidays.json
   输出：起点 2024-01-01 星期一
         终点 2024-01-31 星期三
         自然日差 30 天
         工作日差 22 天（周末 8 天，假期 1 天：元旦）
         完整周数 4 周，余 2 天
3. 示例二（工作日推算）：
   输入：python date_calculator.py --from 2024-09-25 --add-workdays 5 --holidays holidays.json
   输出：2024-09-25 起第 5 个工作日是 2024-10-08（跳过 9-28 至 10-07 的假期与周末）
4. 示例三（年份统计）：
   输入：python date_calculator.py --year 2024
   输出：2024 年共 366 天，周末 104 天，假期 11 天，工作日 251 天
5. 示例四（周信息）：
   输入：python date_calculator.py --week-of 2021-01-01
   输出：2021-01-01 属于 2020 年第 53 周（星期五），当年第 1 天，按 %U 为第 0 周
6. 示例五（异常输入）：
   输入：python date_calculator.py 2024-02-30 2024-03-01
   输出（stderr）：错误：'2024-02-30' 不是合法日期（2024 年 2 月只有 29 天），退出码 2
7. 示例六（顺序颠倒）：
   输入：python date_calculator.py 2024-03-31 2024-03-01
   输出：提示已自动按时间先后排序，自然日差 30 天，方向为负（终点早于起点）

【六、验收标准】

[ ] 1. 2024-01-01 到 2024-12-31 的自然日差为 365 天，工作日差在无假期表时为 262 天。
[ ] 2. 传入日期顺序颠倒时结果符号为负，且被跳过的天数绝对值与正序一致。
[ ] 3. 2024-02-30、2024-13-01、2023-02-29 三种非法日期均报错且退出码为 2。
[ ] 4. --add-workdays 5 从 2024-09-25 出发，在含国庆假期的表下得到 2024-10-08。
[ ] 5. --add-workdays -3 从 2024-01-03 出发得到 2023-12-28（跨年正确）。
[ ] 6. --year 2024 输出总天数 366、2 月天数 29；--year 2023 输出总天数 365、2 月天数 28。
[ ] 7. --week-of 2021-01-01 输出 ISO 周为 2020 年第 53 周，且 --week-of 2024-12-30
       输出 2025 年第 1 周（跨年归属正确）。
[ ] 8. 假期表中同时包含 2024-09-29 调休上班时，该日被计为工作日。
[ ] 9. --workweek 设置为空时报参数错误，程序不进入无限循环。
[ ] 10. --json 输出可被 json.loads 解析，字段与文档列出的九项一致。
[ ] 11. 相对表达式 +2m 从 2024-01-31 出发得到 2024-03-31（月末处理符合文档描述）。
[ ] 12. --holidays 指向不存在文件时报错并退出码为 2，标准输出为空。
[ ] 13. 同一命令加 --today 2024-03-01 后，两次运行结果完全一致（不依赖真实当前日期）。
[ ] 14. --verbose 输出的跳过明细条数与"周末 + 假期"的统计总数一致。

【七、可选扩展】

1. 加入农历与二十四节气支持（需要自行引入离线节气算法，或允许用户手工维护 JSON 表）。
2. 增加 --ics 导出，把假期表与倒数日导出为 iCalendar 格式文件，供日历软件导入。
3. 支持重复型节日规则（例如"每年 5 月第 2 个星期日"），减少手工维护假期表的成本。
4. 增加 --business-hours 模式，在计算时同时考虑每天 9:00 到 18:00 的工作时段，
   把工作日差换算为工时。
5. 增加 --export csv，把年份统计按月导出为 CSV 供表格软件做排期。

【八、涉及知识点】

- datetime.date、datetime.timedelta、date.fromisoformat 与 strftime/strptime 格式化
- calendar 模块：isleap、monthrange、weekday、Calendar 类与周起始日设置
- ISO 8601 周编号规则与跨年周归属（isocalendar 三元组）
- 闰年判定、大小月、日期区间逐日迭代与迭代上限保护
- 集合运算在假期表去重与调休场景中的应用
- 正则表达式解析多种日期写法与相对表达式
- argparse 参数校验、logging 分级日志、JSON 配置文件的读取与错误定位
- functools.lru_cache 缓存工作日判断结果以提升批量性能
