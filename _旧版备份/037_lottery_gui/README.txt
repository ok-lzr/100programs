【一、项目背景与目标】

课堂点名、年会抽奖、团建分组这类场景，主持人往往需要一个能投到大屏上的随机抽取工具。
网上的在线抽奖网页要么夹杂广告、要么要求登录、要么不能导入自己的名单；而用 Excel 的
RAND 函数随机，观众看不到"滚动过程"，缺少仪式感，也容易被人怀疑结果被内定。

本项目用 tkinter 实现一个本地抽奖点名器：支持导入名单（txt/csv）、大字号滚动动画、
不重复抽取（抽过的人不再出现）、多轮奖项（一等奖 1 名、二等奖 3 名等）、以及结果导出。
关键设计是"抽取过程可复现"——每次抽取同时记录使用的随机种子与当时剩余名单的哈希，
活动结束后可审计，从而消除"被动手脚"的疑虑。

目标用户是教师、班主任、活动主持人、HR。做成之后，把电脑接上投影仪点一下"开始"，
就能得到一个既好看又能自证公平的抽奖过程。

【二、功能需求清单】

1. 核心功能
   1.1 名单导入：支持 .txt（每行一个名字，忽略空行与以 # 开头的注释行）、
       .csv（读取 name 列或第一列，自动跳过表头）、以及手动粘贴到多行文本框。
       导入后显示"已导入 N 人"，并处理重名：默认保留，可在界面上勾选"自动去重"。
   1.2 滚动抽取：点击"开始"后，显示区以每 40~60 毫秒的间隔快速随机展示候选名字，
       模拟老虎机效果；点击"停止"（或再次点击同一按钮，或按空格）立即定格结果。
   1.3 不重复抽取：默认开启"抽过不再抽"，已抽中的人从候选池移除并记入已中奖列表；
       可手动取消该选项以允许重复（例如抽"幸运观众"时允许重复参与）。
   1.4 多轮奖项：支持配置多个奖项，每项包含 名称（如"三等奖"）、人数（如 3）、
       是否批量抽取（一次出 3 个名字）。默认提供 特等奖 1、一等奖 1、二等奖 3、
       三等奖 5、幸运奖 10 五档，可在界面上增删改。
   1.5 批量抽取：人数大于 1 时，滚动结束后一次性显示 N 个名字（用网格或换行排列），
       每个名字字号随人数自动缩小以保证不溢出。
   1.6 结果导出：导出为 CSV（列：序号、奖项、姓名、抽取时间、随机种子）
       与纯文本（适合直接贴到群里）；可选自动附加到"已中奖名单"文件。
   1.7 抽取回滚：误抽时点"撤销本次"，把该批中奖者放回候选池并删除对应记录。
   1.8 可复现审计：每次抽取记录随机种子 seed（secrets 或 random.SystemRandom 生成）、
       抽取时剩余候选池的 SHA256、以及模式（是否去重），写入 records.json。

2. 输入与交互（控件布局与事件绑定）
   2.1 主窗口：Tk()，标题"抽奖点名器"，初始 1000x700，minsize(760, 520)。
       grid 布局三行：row=0 顶部控制条，row=1 主显示区（weight=1），row=2 底部状态栏。
   2.2 顶部控制条 Frame：从左到右依次为
       Button("导入名单")、Button("编辑名单")、Label("奖项") + ttk.Combobox（奖项下拉）、
       Label("人数") + Spinbox(from_=1, to=50)、
       Checkbutton("抽过不再抽", variable=no_repeat_var)、
       Checkbutton("音效", variable=sound_var, 默认关闭)、
       Button("撤销本次")、Button("导出结果")。
       所有控件 pack(side="left", padx=6, pady=8)。
   2.3 主显示区：上方一个大 Label（font=("微软雅黑", 64, "bold")、前景 #C0392B，
       锚点 center）显示当前滚动名字或最终结果；下方一个只读的 Text 或 Listbox
       （高 8 行）显示本轮已抽中名单（格式"三等奖：张三、李四、王五"）。
       批量抽取多人时，大字 Label 改为显示"共 N 人"，
       并在下方用一个 Label 网格（每行最多 5 个，字号 32）列出所有中奖者。
   2.4 底部状态栏：左 Label 显示"候选池剩余 X 人 / 总计 Y 人"，
       中 Label 显示最近一次操作的提示，右 Label 显示"已抽 N 轮"。
   2.5 核心按钮：主显示区下方居中放一个大 Button（宽 16、高 3、字号 20），
       文字在"开始"与"停止"之间切换；绑定 <Button-1>。
   2.6 事件绑定（必须全部实现）：
       - 空格键（<space>）等效于点击开始/停止，便于主持人用遥控翻页笔触发。
       - <Return> 等效于开始/停止；<Escape> 关闭进行中的滚动并保留上一位中奖者。
       - <Control-z> 绑定到"撤销本次"。
       - <Control-o> 绑定到"导入名单"，<Control-s> 绑定到"导出结果"。
       - 每个按钮的 command 使用具名方法（on_start_stop、on_import 等），不用匿名 lambda 堆叠。
       - root.protocol("WM_DELETE_WINDOW", self.on_close)：若存在未导出的抽取记录则询问导出。
   2.7 交互流程（必须按此描述实现）：
       (a) 启动 → 自动尝试读取上次的名单缓存 names.json，若为空则提示先导入名单；
       (b) 导入名单 → 状态栏显示"已导入 128 人"，主显示区显示"准备就绪"；
       (c) 点"开始" → 按钮文字变"停止"，启动 after 循环，每次从候选池随机取一个
           （或 N 个）名字刷新大字 Label，同时禁用"导入名单"与奖项下拉；
       (d) 点"停止" → after_cancel 停掉动画，用同一帧的随机结果作为最终结果，
           大字 Label 加金色背景闪烁 3 次（用 after 连续切换背景色），
           记录中奖者、更新候选池、追加到下方名单、写 records.json；
       (e) 候选池为空时点"开始" → 弹出"候选人已抽完"提示，不启动动画。

3. 输出与展示
   3.1 滚动阶段的随机名字必须来自候选池（不是全体名单），保证"停止即结果"的真实性。
   3.2 中奖结果在大字 Label 上的字号自动调整：1 人 64pt、2~5 人 40pt、6 人以上 32pt。
   3.3 导出 CSV 使用 utf-8-sig 编码（便于 Excel 直接打开不乱码），表头为
       序号,奖项,姓名,抽取时间,随机种子。
   3.4 全部抽取结束后可点"导出结果"，也可在关闭时自动导出到
       <名单目录>/lottery_result_YYYYMMDD_HHMMSS.csv。
   3.5 状态提示统一显示在底部中间 Label，5 秒后清空（用 after 实现）。

4. 异常与边界处理
   4.1 名单为空时点开始：提示"请先导入名单"，不进入滚动状态。
   4.2 名单只有 1 人：允许抽取但提示"候选池仅 1 人，结果无随机性"。
   4.3 抽取人数大于候选池剩余人数：提示"候选池只剩 X 人，无法抽取 N 人"并中止。
   4.4 名单含超长名字（超过 20 字符）：显示时截断为前 18 字符加 "…"，导出时保留完整。
   4.5 名单含空行/首尾空格：导入时统一 strip 并过滤空行；全角空格也视为空白。
   4.6 重复抽取动画未停止就点导入名单：按钮在滚动期间处于 disabled 状态，从根源避免。
   4.7 撤销时无记录：提示"没有可撤销的抽取记录"。
   4.8 records.json 损坏：重命名为 records.json.bak 并从空记录继续，状态栏提示一次。
   4.9 导出路径不可写：弹出"另存为"对话框让用户改选位置。
   4.10 窗口被最小化或失去焦点时：动画继续运行（after 不受焦点影响），
        恢复后状态一致；不因动画而占用 100% CPU（每次 after 间隔不小于 40 毫秒）。
   4.11 动画期间不阻塞 UI：不得使用 time.sleep 或 while 循环空转。

【三、技术要求与约束】

1. 语言与版本：Python 3.10 及以上；使用标准库 tkinter（含 ttk）。
2. 允许使用的库：仅使用标准库，包括 tkinter、tkinter.ttk、tkinter.filedialog、
   tkinter.messagebox、random、secrets、hashlib、json、csv、pathlib、datetime、
   time、dataclasses、logging、typing。
3. 禁止事项：禁止用 time.sleep 实现动画（必须用 after 回调）；
   禁止在抽奖结果中使用 random.random() 之外还混入未记录的随机源（影响可复现）；
   禁止把抽取算法写死在界面回调里（必须抽成独立模块以便单测）；
   禁止在未告知用户的情况下修改原始名单文件。
4. 代码组织：至少包含 lottery.py（抽取逻辑，纯逻辑无 UI）、names.py（名单导入与清洗）、
   records.py（记录与导出）、app.py（界面与动画）。抽取入口签名固定为
   draw(pool: list[str], count: int, rng: random.Random) -> list[str]，
   其中 rng 由 random.Random(seed) 构造，seed 由 secrets.randbits(64) 生成并记录。
5. 编码规范：类型注解与 docstring 齐全；所有文件读写显式指定编码；
   app.py 中的动画状态用 AppState 数据类集中管理；回调方法统一 on_ 前缀。

【四、设计要点】

1. 数据结构：
   - AppState：pool: list[str]（候选池），drawn: list[str]（已中奖，用于去重），
     rolling: bool，current_seed: int | None，prize_index: int，
     records: list[DrawRecord]。
   - DrawRecord：round_no: int，prize: str，names: list[str]，seed: int，
     ts: str，pool_hash: str。
   - Prize：name: str，count: int，batch: bool。
   - DEFAULT_PRIZES = [("特等奖", 1), ("一等奖", 1), ("二等奖", 3),
     ("三等奖", 5), ("幸运奖", 10)]。
2. 关键算法或流程：
   2.1 名单清洗流程：逐行读取 → strip() → 过滤空行与以 "#" 开头 → 去除 UTF-8 BOM →
       若勾选"自动去重"则用 dict.fromkeys 保序去重 → 与已中奖名单求差集得到候选池。
   2.2 抽取算法：使用 rng.sample(pool, k=count)（不重复的无偏抽样）；
       当 k == 1 时等价于 rng.choice；当 k == len(pool) 时等价于整体打乱。
       严禁使用 sorted(pool, key=lambda _: rng.random()) 这种低效且易出错的写法。
   2.3 动画流程（after 驱动）：
       (a) on_start_stop 进入滚动：self.rolling = True，按钮文字改"停止"，
           after_id = root.after(50, self.tick)；
       (b) tick 方法：从候选池 rng.choice 取一个名字刷新大字 Label，
           再次 root.after(50, self.tick) 形成循环；
       (c) 停止时先 root.after_cancel(after_id) 并置 after_id = None，
           防止残留回调在停止后继续刷新（这是本项目的经典 bug 点）；
       (d) 帧间隔在滚动前 1 秒为 40 毫秒，之后放慢到 80 毫秒，营造减速感。
   2.4 公平性审计：每次抽取时计算 pool_hash = sha256("|".join(sorted(pool)).encode())
       并写入记录。任何人可用同样的种子、同样的候选池和同样的参数复现结果：
       提供 --verify 命令行参数，读取 records.json，用记录的 seed 与 pool_hash
       重放抽取并与记录的 names 比对，输出"一致/不一致"。
   2.5 批量抽取的显示布局：把中奖者按每行 5 个切成若干行，
       用一个 Frame 内嵌 grid 的 Label 网格显示，字号随行数递减（40/34/28/24）。
   2.6 撤销流程：从 records 弹出最后一条 → 把 names 中的名字移出 drawn →
       重新计算候选池 → 刷新界面与状态栏 → 重写 records.json。
3. 接口或命令设计：
   运行：python app.py [--names names.txt] [--no-repeat] [--seed 12345]
   审计：python app.py --verify records.json
   纯逻辑调用示例（供测试使用）：
       from lottery import draw
       import random
       draw(["a","b","c","d"], 2, random.Random(42)) -> 每次运行结果相同，例如 ['c','a']

【五、运行方式与示例】

安装：无需安装（Linux 需要 python3-tk）。
运行：
   python app.py
   python app.py --names .\class3.txt --no-repeat
   python app.py --verify .\records.json

names.txt 示例：
   # 三年二班名单
   张三
   李四
   王五
   赵六

示例一（单人抽取流程）：
   操作：导入 names.txt（4 人）→ 奖项选"一等奖"、人数 1 → 点击"开始"
   界面：大字区域以 40 毫秒间隔快速切换 张三/李四/王五/赵六
   操作：0.8 秒后点击"停止"
   界面：大字显示"王五"并金色闪烁 3 次；下方名单出现"一等奖：王五"
   状态栏：候选池剩余 3 人 / 总计 4 人 | 已抽 1 轮

示例二（批量抽取）：
   操作：奖项选"幸运奖"、人数 3 → 开始 → 停止
   界面：大字显示"共 3 人"，下方 3 个 40pt 标签横向排列：李四 赵六 张三
   状态栏：候选池剩余 0 人 / 总计 4 人 | 已抽 3 轮

示例三（导出结果）：
   输入：点击"导出结果"→ 保存为 result.csv
   输出（result.csv，utf-8-sig）：
   序号,奖项,姓名,抽取时间,随机种子
   1,一等奖,王五,2024-05-20 14:03:11,12738465019283746550
   2,幸运奖,李四,2024-05-20 14:04:02,9801726354019283746

示例四（异常输入）：
   操作：名单为 4 人，已抽 3 人后奖项仍选"幸运奖"、人数 3 → 点击"开始"
   界面：弹出提示 "候选池只剩 1 人，无法抽取 3 人"；动画不启动，按钮保持"开始"

示例五（审计复现）：
   输入：python app.py --verify records.json
   输出：
   第 1 轮 一等奖 王五 ... 一致
   第 2 轮 幸运奖 李四/赵六/张三 ... 一致
   审计完成：2 轮全部一致，随机过程可复现

【六、验收标准】

[ ] 导入含空行与 # 注释的 txt 后，人数统计正确。
[ ] 导入含 BOM 的 CSV 后，第一个姓名不带多余字符。
[ ] 勾选"自动去重"后重名只保留一个，不勾选则全部保留。
[ ] 滚动期间点击"停止"，结果必定是候选池中存在的名字。
[ ] 连续 20 次"抽 1 人"且开启去重，20 次结果互不相同。
[ ] 关闭去重后同一人可被重复抽中。
[ ] 抽取人数超过候选池剩余时给出提示且不产生记录。
[ ] 停止动画后点击"开始"不会出现两个动画同时运行（不会闪烁异常）。
[ ] 空格键与回车键都能触发开始/停止，Escape 可中止滚动。
[ ] 撤销本次后该名字回到候选池，状态栏剩余人数 +N。
[ ] 导出的 CSV 用 Excel 打开中文不乱码，字段与顺序符合规范。
[ ] records.json 中每条记录都含 seed 与 pool_hash。
[ ] --verify 能用记录的种子复现全部抽取结果并输出"一致"。
[ ] 动画长时间运行（> 2 分钟）时 CPU 占用低于 15%。
[ ] 名单只有 1 人时给出"结果无随机性"的提示。
[ ] 关闭程序时若存在未导出记录会询问是否导出。

【七、可选扩展】

1. 增加滚动音效（winsound 在 Windows 可用）与中奖庆祝动画（Canvas 粒子）。
2. 增加"分组模式"：把名单随机均分为若干组并导出，用于团建分组。
3. 增加全屏/演示模式：隐藏控制条、放大字体，只保留一个巨大按钮。
4. 增加头像显示：读取 names.csv 中的 photo 列，滚动时同步显示候选人照片。
5. 增加多机同步：通过本地 WebSocket 服务把抽取结果推送到手机端查看。

【八、涉及知识点】

- tkinter after/after_cancel 实现定时动画与状态机（避免 time.sleep 阻塞 UI）
- random.Random(seed) 的可复现随机与 random.SystemRandom/secrets 的种子来源
- random.sample 的无偏不重复抽样
- 控件状态管理（state="disabled"）与按钮文字切换
- ttk.Combobox、Spinbox、Checkbutton 的变量绑定（StringVar/IntVar/BooleanVar）
- 键盘事件绑定与遥控翻页笔（模拟空格/回车）的兼容
- CSV/JSON 持久化与 utf-8-sig 编码的实际用途
- 哈希指纹用于过程审计与复现验证
