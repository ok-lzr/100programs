【一、项目背景与目标】

聚餐后 AA 是最容易闹别扭的环节：有人没喝酒、有人只点了一份沙拉、还有人先垫付了整单。
手算容易出错，尤其是小费、折扣、抹零之后每个人该付多少分。这个工具按两种模式分摊：
按人头平均分摊，或者按各人点的项目精确分摊，并把小费与折扣按比例摊到每个人身上，
最后用“最大余额法”保证每人金额之和严格等于总额，一分不差。

目标用户是聚餐组织者与同事小团体、需要分摊房租水电的合租室友、以及学习浮点精度与
金额舍入问题的编程初学者。设计重点是金额必须用整数分（cent）计算，输出前才转成元。

做完之后应当能拿来干这些事：8 个人吃饭总额 486 元加 10% 小费，算出每人该付多少；
按项目分摊时把共享的菜按参与人数二次分摊；用 --paid-by 记录谁垫付了钱，输出应收应付
的对账表；把明细导出成 CSV 发到群里。

【二、功能需求清单】

1. 核心功能
   1.1 按人头分摊：总金额除以人数，余数按顺序分给前若干人，保证合计精确。
   1.2 按项目分摊：账单文件里每行一个消费项，含项名、金额、参与人列表。
   1.3 共享项二次分摊：一个项目有多人参与时，该项金额在参与人之间再次均分。
   1.4 小费：--tip 10% 或 --tip 30（元）两种写法；小费可按人头或按各人消费额比例分摊。
   1.5 折扣：--discount 20% 或 --discount 50（元），按各人消费额比例摊回。
   1.6 抹零：--round 0.01（分）或 --round 1（元），把每人金额向上取整到指定精度，
       抹零产生的差额记入 --round-target 指定的人或按“公摊”单独列出。
   1.7 垫付对账：--paid-by 张三=486 记录谁付了整单，输出每人应付与应补金额。
   1.8 导出：--output result.csv 写出每人的明细与合计。

2. 输入与交互
   2.1 简单模式：python split.py --total 486 --people 8 --tip 10%
   2.2 名单参数：--names "张三,李四,王五" 或 --names-file names.txt 每行一个名字。
   2.3 按项目模式：python split.py --bill bill.txt --tip 10% --discount 20
   2.4 bill.txt 格式（每行一项，用竖线分隔）：
       烤鱼 | 128 | 张三,李四,王五
       沙拉 | 32 | 李四
       包间费 | 50 | 全员
       “全员”表示所有参与分摊的人；金额允许两位小数或整数。
   2.5 固定分摊：--fixed "张三=50" 表示某人只付固定金额（如小孩半价），
       剩余金额由其余人分摊。
   2.6 交互模式：不带参数运行则逐项询问总额、人数、小费率、折扣。
   2.7 参数：--json 输出机器可读结果；--verbose 显示每人的计算过程；
       --show-formula 打印分摊公式与舍入差额的来源。

3. 输出与展示
   3.1 汇总输出：
       总额：486.00 元
       小费 10%：48.60 元
       折扣 -20.00 元
       应付合计：514.60 元
       人数：8
       每人应付：64.33 元（前 4 人），64.32 元（后 4 人）
       合计校验：514.60 元（误差 0.00 元）
   3.2 逐人明细输出：
       张三：项目分摊 42.67 + 小费 4.27 - 折扣 1.76 = 45.18 元
   3.3 垫付对账输出：
       张三 已垫付 486.00 元，应补 -420.70 元（应收 420.70 元）
       李四 应付 45.18 元
   3.4 抹零输出：
       抹零到 1 元后：每人 65 元，多收 5.40 元记入公摊
   3.5 --json 输出 {"total":486.0,"tip":48.6,"discount":20.0,"grand_total":514.6,
       "shares":[{"name":"张三","amount":64.33}]}。
   3.6 终端输出金额统一保留两位小数，负数显示为 -420.70。

4. 异常与边界处理
   4.1 总额非正数时打印 “错误：总额必须大于 0”，退出码 2。
   4.2 人数为 0 或负数时打印 “错误：人数必须大于等于 1”。
   4.3 小费或折扣导致总额为负时打印 “错误：折扣后金额为负，请检查参数”。
   4.4 项目中的参与人不在名单里时打印 “错误：第 3 行的参与人 '王五' 不在名单中”，
       退出码 2，并列出名单。
   4.5 项目金额无法解析时给出 “错误：第 2 行金额 '12x' 不是有效数字”。
   4.6 折扣大于消费额时按消费额封顶并把多余部分记为 0，同时在 --verbose 中说明。
   4.7 固定分摊金额之和大于总额时打印
       “错误：固定分摊合计 520.00 元已超过总额 486.00 元”。
   4.8 空账单文件或全部行都是注释时打印 “错误：账单为空”，退出码 2。
   4.9 舍入差额必须显式展示，禁止悄悄丢钱或多收钱。

【三、技术要求与约束】

1. 语言与版本：Python 3.10 及以上。
2. 允许使用的库：仅使用标准库，需要 argparse、csv、json、decimal、pathlib、
   dataclasses、typing、logging。
3. 禁止事项：禁止用 float 累加金额后直接输出（必须全程用整数分或用
   decimal.Decimal 且明确 quantize 规则）；禁止用 round() 处理金额（银行家舍入会
   造成意外）；禁止在分摊结果中出现合计不等于总额的情况。
4. 代码组织：
   4.1 金额工具：parse_amount(text) -> int（元转分）、format_amount(cents) -> str、
       apply_percent(cents, percent) -> int。
   4.2 分摊核心：split_even(total_cents, weights) -> list[int]（按权重分配并处理余数）、
       distribute_remainder(shares, remainder, order) -> list[int]。
   4.3 数据结构：BillItem、PersonShare、SplitResult 三个 dataclass。
   4.4 流程函数：split_by_headcount、split_by_items、apply_tip_and_discount、
       reconcile_payments、export_csv。
   4.5 main() 负责读参数、读文件、选择分摊模式、输出。
5. 编码规范：类型注解与 docstring；所有金额变量以 _cents 结尾以标明单位；
   禁止出现裸浮点金额变量；在 docstring 中写明舍入规则。

【四、设计要点】

1. 数据结构：
   1.1 BillItem：dataclass，字段 line_no: int、name: str、amount_cents: int、
       participants: list[str]（"全员" 展开为名单副本）。
   1.2 PersonShare：dataclass，字段 name: str、items_cents: int、tip_cents: int、
       discount_cents: int、fixed_cents: int、total_cents: int。
   1.3 SplitResult：dataclass，字段 grand_total_cents、shares: list[PersonShare]、
       remainder_cents: int、payments: dict[str, int]。
2. 关键算法或流程：
   2.1 最大余额法：先算每人的理论份额（整数除法取整），把余数按“小数部分从大到小、
       相同则按名单顺序”依次加 1 分，直到分完。这样合计严格等于总额。
   2.2 按项目分摊流程：遍历每个 BillItem -> 参与人数为 k 时按最大余额法把该项金额
       分给参与人 -> 累加到各自 items_cents。
   2.3 小费分摊：按人头模式用最大余额法平均分；按项目模式按各人 items_cents 为权重
       分配，权重全为 0 时退化为平均分。
   2.4 折扣分摊：同小费逻辑，结果记为负数；若折扣总额超过消费额，按比例缩减到不超。
   2.5 抹零：对每人 total_cents 按 --round 精度向上取整，累加差额记入 remainder_cents；
       若指定 --round-target 则全部差额由该人承担。
   2.6 对账：应付 total_cents 减去已垫付 payments_cents，正数为应补，负数为应收。
3. 接口或命令设计：
   3.1 parse_amount(text: str) -> int
   3.2 split_even(total_cents: int, weights: list[int]) -> list[int]
   3.3 split_by_items(items: list[BillItem], names: list[str]) -> dict[str, int]
   3.4 build_result(items, names, tip, discount, fixed, round_to) -> SplitResult
   3.5 命令行：--total、--people、--names、--names-file、--bill、--tip、--discount、
       --fixed、--round、--round-target、--paid-by、--output、--json、--verbose。

【五、运行方式与示例】

1. 运行准备：无需安装依赖。
2. 按人头分摊（含小费）：
   python split.py --total 486 --names "张三,李四,王五,赵六" --tip 10%
   输出：
   总额：486.00 元
   小费 10%：48.60 元
   应付合计：534.60 元
   人数：4
   每人应付：133.65 元
   合计校验：534.60 元（误差 0.00 元）
3. 除不尽时的余数分配：
   python split.py --total 100 --people 3
   输出：
   每人应付：33.34 元（前 1 人），33.33 元（后 2 人）
   合计校验：100.00 元（误差 0.00 元）
4. 按项目分摊（bill.txt 三行）：
   python split.py --bill bill.txt --names "张三,李四,王五" --tip 10% --discount 20
   输出（节选）：
   烤鱼 128.00 元 分摊：张三 42.67 李四 42.67 王五 42.67
   沙拉 32.00 元 分摊：李四 32.00
   包间费 50.00 元 均分给 3 人
   张三：项目 59.33 + 小费 5.93 - 折扣 2.00 = 63.26 元
   合计校验：189.79 元（误差 0.00 元）
5. 垫付对账：
   python split.py --total 486 --people 8 --tip 10% --paid-by "张三=486"
   输出：
   张三 已垫付 486.00 元，应收 420.70 元
   其余 7 人各应付 64.33 元
6. 抹零：
   python split.py --total 486 --people 8 --round 1 --round-target 公摊
   输出：
   抹零到 1 元后：每人 65 元，多收 3.40 元记入公摊
7. 异常输入示例：
   python split.py --total -10 --people 3
   输出：错误：总额必须大于 0
   退出码：2
   python split.py --bill bad.txt --names "张三,李四"
   输出：错误：第 3 行的参与人 '王五' 不在名单中，当前名单：张三, 李四
   退出码：2
   python split.py --total 486 --people 8 --discount 600
   输出：错误：折扣后金额为负，请检查参数

【六、验收标准】

[ ] 100 元 3 人分摊的结果为 33.34、33.33、33.33 且合计 100.00
[ ] 任意参数下分摊结果之和严格等于应付合计，误差为 0.00 元
[ ] --tip 10% 与 --tip 30 两种写法等价于同一金额时结果一致
[ ] 按项目分摊时单项只由参与人承担，未参与的人该项为 0
[ ] 包间费等“全员”项目被正确均分给所有人
[ ] 折扣金额按比例摊回且不超过各人消费额
[ ] 抹零差额被显式列出，不会凭空消失
[ ] --paid-by 对账输出应收为正、应补为正便于阅读
[ ] 固定分摊生效后剩余金额由其余人分摊
[ ] 账单文件中参与人不在名单时给出带行号的错误
[ ] 空账单、金额非法、名单缺失三种情况都返回退出码 2
[ ] 输出 CSV 的每行合计等于终端显示金额
[ ] 源码中金额计算全部以整数分为单位，无裸浮点累加
[ ] 未使用 round() 处理金额

【七、可选扩展】

1. 支持多币种与汇率，输出时按币种分组。
2. 支持多笔垫付（--paid-by "张三=200" --paid-by "李四=286"）并给出最少转账笔数方案。
3. 增加微信或支付宝转账备注文本生成，直接复制到群里。
4. 支持服务费与税费同时存在的叠加顺序配置（先税后费或先费后税）。
5. 增加历史账单归档，统计某人一个月的聚餐支出。

- 金额计算使用整数分避免浮点误差
- decimal.Decimal 与 quantize 的使用场景
- 最大余额法（最大余数法）分配整数份额
- 按权重分摊与比例缩放的实现
- 加权平均与向上取整的差异
- dataclass 组织账单项与个人份额
- 自定义文本格式解析（竖线分隔 + 字段校验）
- 对账逻辑：应付与垫付的正负号约定
- csv 导出与中文编码
