# 020 · 正则批量替换工具

> ★★☆☆☆　难度 2.0 / 5　·　001–020 · 找回手感
> 3 ~ 4 小时，分 4 次　·　1 个文件（regex_replace.py），约 180 行　·　只用 Python 自带功能
>
> **规矩：这份任务卡只给思路和语法点，一行代码都没有。代码由你自己写。**

**一句话**：用正则表达式在多份文件里查找替换，带预览、备份和回滚

## 为什么做它

正则表达式是文本处理的放大镜：找出所有邮箱、把所有「2026/10/01」改成「2026-10-01」、把日志里的时间戳统一格式。它一开始看着像天书，但只要你亲手写过三五个，就会发现它其实就那几招。这个项目也是本阶段最后一关，它会用到前面所有项目的经验：遍历文件、预览、备份、回滚。

## 做完是什么样

程序扫描一个文件夹里的文本文件，用你给的正则找出所有匹配：先打印「将替换 14 处」和前三处的前后对照，你确认后才真的替换；替换前每个文件都备份成 .bak，替换后能一键回滚；结束时给出报告，列出每个文件改了几处。约 180 行，一个文件。

## 会练到的语法

`import re`　`findall 查找全部`　`基本元字符（数字、字母、重复次数）`　`字符集`　`sub 替换`　`捕获分组与引用`　`编译正则`　`遍历文件夹`　`备份文件`　`预览模式`

> 新东西是正则表达式：一套用来描述「什么样的文字」的迷你语言。这一关是分水岭，学完你会发现很多以前要写几十行的判断，现在一行就够了。

## 关卡 1 · 先用它找人：找出所有邮箱和手机号

**建议用时**：30 分钟

### 做出这样就算过

程序里写死一段混杂的文本（自己编：几个邮箱、几个手机号、几个日期、一些废话），运行后输出三行：找到 3 个邮箱、2 个手机号、4 个日期，并把它们列出来。

### 怎么想（步骤）

1. 新建 regex_replace.py，写死一段测试文本，把要找的三类东西都塞进去，再故意放几个「像但不是」的干扰项（比如缺一位的手机号）
2. 引入自带的正则功能，用它的查找全部功能：给一个「模式」，把符合模式的片段全都挑出来
3. 邮箱的模式：一串字母数字，一个 at 符号，再来一串字母数字，一个点，最后是字母。先只处理这种简单情况
4. 手机号的模式：一位数字 1 打头，后面跟十位数字。用重复次数的写法，别把十位数字写十遍
5. 日期的模式：四位数字、短横线或斜杠、两位数字、短横线或斜杠、两位数字。三种都试一遍，看哪些干扰项能识别、哪些识别不了

### 要用到的语法点

- **import re**：自带的正则模块，查找、替换、切分都能做
- **查找全部**：给它模式和文本，它把符合的全部找出来，返回一个列表
- **数字与字母的简写**：反斜杠加 d 表示数字，加 w 表示字母数字下划线——用简写比写一大堆字符集清楚
- **重复次数**：大括号里写个数表示「重复几次」，写两个数字表示「几次到几次」
- **字符集**：方括号里列出允许出现的字符，比如数字或短横线，表示「这里面任意一个」

### 做完了自己检查

- [ ] 三个邮箱全部找到，不多不少
- [ ] 手机号数量正确，缺一位的那个没有被算进去
- [ ] 四种日期写法都能识别（短横线和斜杠两种分隔符）
- [ ] 同一段文本里三类都能同时找出来
- [ ] 把模式改宽松一点，观察能多找出什么（比如把后面的位数要求去掉）

### 卡住看这里

- 把整段文本都匹配上了：模式写得太宽松，加上前后边界（比如要求在非字母数字之后开始）
- 一个都找不到：先拿一个最简单的模式试（比如只找数字），确认调用方式对了再逐步加复杂度
- 方括号里的短横线被当成了范围：短横线放在字符集的开头或结尾就表示它自己

### 常见坑

- 以为正则会「理解」你要什么（它只认模式，不认语义；写完必须拿真实文本验证）
- 把点号当成「任意字符」又当成「句号」用（点号默认匹配任意字符，要匹配真正的点得加转义）

## 关卡 2 · 把日期格式统一换掉

**建议用时**：30 分钟

### 做出这样就算过

把测试文本里所有「2026/10/01」这种斜杠日期换成「2026-10-01」短横线日期，其他内容一个字不动；替换后打印原文和结果各一遍，并输出「共替换 4 处」。

### 怎么想（步骤）

1. 用替换功能：给它模式、替换成什么、原文，它返回替换后的新文本
2. 替换内容里怎么保留原来的数字？用括号把要保留的部分圈起来（这叫捕获分组），在替换内容里按顺序引用它们
3. 想清楚分组怎么分：年一组、月一组、日一组，替换内容里用分隔符拼回去
4. 注意返回值：替换不会改动原字符串，必须用新变量接住结果——这是最容易犯的错
5. 验证：打印替换前后的文本对比，并且数一数替换了几处（替换功能能告诉你次数，或者用查找全部数一数）

### 要用到的语法点

- **替换功能**：给模式、替换内容、原文本，返回替换后的新文本；默认替换全部
- **捕获分组**：用圆括号把模式的一部分圈起来，替换时就能把那部分原样搬过去
- **引用分组**：替换内容里用反斜杠加序号引用第几个分组，序号从 1 开始
- **结果要接住**：字符串本身不可改变，替换的结果是一个新字符串，必须用变量接住
- **替换次数**：替换功能可以同时告诉你换了几处，也可以自己用查找数一遍

### 做完了自己检查

- [ ] 斜杠日期全部变成短横线日期，年月日的数字没变
- [ ] 文本里本来就有短横线日期的地方没有被二次改动
- [ ] 替换处数跟你手工数的一致
- [ ] 其他内容（邮箱、手机号、废话）一字未动
- [ ] 打印原文时原文确实没变（说明你用的是新变量）

### 卡住看这里

- 替换结果没生效：忘了用变量接住返回值
- 年月日顺序乱了：分组的顺序和引用的序号对不上，先把分组挨个打印出来看看
- 本该替换的没换：模式里的分隔符只写了斜杠，没考虑空格或其它写法

### 常见坑

- 把替换结果又写回原变量却写错了名字，导致下一步用的还是旧文本
- 分组引用序号从 0 开始数（它是从 1 开始的）

## 关卡 3 · 多文件先预览，不许直接改

**建议用时**：35 分钟

### 做出这样就算过

程序扫描一个文件夹里所有文本文件，对每个文件打印：文件名、将替换几处、前三处的前后对照（替换前 → 替换后）。整个过程**一个文件都不改**。最后汇总「共 3 个文件、14 处匹配」。

### 怎么想（步骤）

1. 建一个测试文件夹，放几个文本文件，里面故意安排不同数量的日期；再放一个二进制文件（比如图片）当干扰
2. 遍历文件夹，只处理后缀是文本的那些（先按后缀简单过滤）
3. 对每个文件：读出全文，用查找全部数出匹配数量；再用替换功能得到新文本，用两份文本对照找出前几处差异
4. 打印预览：文件名、数量、前三处。前三处可以直接用查找全部的结果跟替换后的结果对比，也可以把原文按匹配切开再拼回去看
5. 汇总所有文件的数量，打印总计。跳过没有匹配的文件（不打印或者单独列一行都行）

### 要用到的语法点

- **遍历并过滤后缀**：只看 .txt、.md 这类文本文件，别的跳过
- **按匹配切开**：用切分功能把原文按匹配位置切成几段，就能看出每处匹配前后的内容
- **切片取前几个**：只要前三处，用切片取列表的前三项
- **读文件失败要跳过**：二进制文件按文本读会失败，接住异常并把它记成「跳过」
- **汇总计数器**：两个计数器：文件数、匹配数；每处理一个文件就更新

### 做完了自己检查

- [ ] 每个文件的匹配数量跟手工数的一致
- [ ] 预览里能看到替换前后的差别（能看出格式从斜杠变成了短横线）
- [ ] 跑完之后打开文件确认：一个字都没改
- [ ] 二进制文件被跳过并记录，程序不崩
- [ ] 总计数字等于各文件数量之和

### 卡住看这里

- 二进制文件让程序崩了：读文件时要接住异常，把它算作跳过
- 预览看不到前后对照：用切分功能把原文切开，奇数段是匹配、偶数段是普通文字
- 数量为 0 的文件也打印了一堆空行：先判断数量再打印

### 常见坑

- 预览阶段就顺手写了文件（这一关的纪律就是：预览和修改必须是两次运行）
- 把整个文件夹递归扫进去，把备份文件也算了进来

## 关卡 4 · 真替换，还要能一键回滚

**建议用时**：35 分钟

### 做出这样就算过

程序加一个确认步骤：确认后对每个文件先备份成同名加 .bak 后缀，再写回替换后的内容；跑完打印报告「3 个文件、共替换 14 处、备份 3 份」。再加一个回滚功能：把所有 .bak 还原回去，文件内容跟替换前一模一样。

### 怎么想（步骤）

1. 替换前先备份：把原文件复制一份，名字后面加 .bak；如果备份已经存在就跳过备份（不要用旧备份覆盖新内容）
2. 再写回替换后的内容（覆盖写，指定编码）
3. 报告里列出每个文件改了几处，以及是否备份成功
4. 回滚功能：遍历文件夹里的 .bak 文件，把它们复制回去掉后缀的名字，然后可以选择删掉 .bak
5. 测试完整闭环：先替换，去看文件确实改了；再回滚，去看文件确实恢复了；对比一下跟最初的备份是否一致

### 要用到的语法点

- **复制文件**：自带功能可以复制文件，给它源路径和目标路径
- **判断备份是否存在**：已经存在就跳过，避免用被改过的内容覆盖掉真正干净的备份
- **覆盖写入**：写回原文件时用覆盖模式，指定编码
- **去掉后缀**：还原时要把 .bak 这个名字后缀去掉，路径对象和字符串都有现成的办法
- **二次确认**：把用户输入统一处理后只认明确的肯定，其余一律不动手

### 做完了自己检查

- [ ] 替换后文件内容确实变了，改动位置跟预览一致
- [ ] 每个被改的文件都有对应的 .bak
- [ ] 回滚后文件内容跟替换前逐字一致（用备份对比或者自己核对）
- [ ] 拒绝确认时一个文件都不动、也不产生 .bak
- [ ] 修改过程中途失败时，已经处理过的文件也能靠 .bak 还原

### 卡住看这里

- 回滚后文件没变：备份是在替换之后才做的（顺序反了，等于备份了改过的内容）
- 文件名还原错了：去掉后缀时把名字里的点也去掉了，要只去掉最后那个 .bak
- 替换到一半出错，文件毁了一半：先全部备份完再统一替换，或者一个文件一个文件地「备份 + 替换」

### 常见坑

- 没有确认环节直接替换（正则写错一个字符就可能毁掉一批文件，这是最危险的一关）
- 把 .bak 当成待处理的文本文件又扫了一遍
