# 013 · 批量文件重命名工具

> ★½☆☆☆　难度 1.5 / 5　·　001–020 · 找回手感
> 3 小时左右，分 4 次　·　1 个文件（bulk_renamer.py）+ 一个自动生成的记录文件，约 160 行　·　只用 Python 自带功能
>
> **规矩：这份任务卡只给思路和语法点，一行代码都没有。代码由你自己写。**

**一句话**：按序号、前后缀、时间批量改名，带预览和撤销

## 为什么做它

手机导出来的照片叫 IMG_20261001_183000.jpg 这种名字，几十张一起看根本分不清。这个项目让程序替你改名——但它是你第一个**会真的动你硬盘上文件**的程序，所以最重要的不是改名本身，而是三件事：**先预览、先备份、能撤销**。这三件事是专业和闯祸的分界线。

## 做完是什么样

程序问你文件夹路径和命名规则，先打印一张「旧名 → 新名」的对照表让你确认，你输入确认之后才真的改名；每次改名都会写进一个记录文件，之后运行「撤销」能把文件名一个不差地还原回去。约 160 行，一个文件。

## 会练到的语法

`import pathlib`　`遍历文件夹`　`判断文件与文件夹`　`提取扩展名`　`字符串格式化补零`　`排序`　`重命名文件`　`文件是否存在判断`　`读写记录文件`　`异常处理`

> 新东西是「操作文件」和「操作要有回退方案」。从这一关开始，程序有了破坏力，所以每一步都要能被撤回。

## 关卡 1 · 先学会看：列出文件夹里有什么

**建议用时**：25 分钟

### 做出这样就算过

运行后给一个文件夹路径，打印出里面每个文件的名字和大小（按 KB 显示，保留一位小数），文件数量在最后汇总。文件夹和文件要能区分开显示。

### 怎么想（步骤）

1. 新建 bulk_renamer.py，以及一个专门用来做实验的文件夹（比如在项目文件夹里新建一个 test_files，随手放几个文件进去，别拿重要文件练手）
2. 用自带的功能遍历这个文件夹里的每一项
3. 每一项都判断一下：是文件还是文件夹，分开显示
4. 取大小是按字节给的，自己换算成 KB（除以 1024），保留一位小数
5. 最后打印一共几项，并处理「路径不存在」的情况——给提示而不是崩掉

### 要用到的语法点

- **import pathlib**：专门用来处理路径和文件的模块，比拼字符串靠谱得多
- **遍历文件夹**：把一个文件夹里的每一项一个个拿出来
- **判断是文件还是文件夹**：每一项自己知道它是什么，用一个方法就能问出来
- **取文件名和大小**：名字和大小都是现成的属性，不用自己去切字符串
- **单位换算**：字节除以 1024 就是 KB，再除以 1024 是 MB

### 做完了自己检查

- [ ] 文件名、大小、汇总三样都打印出来了
- [ ] 大小换算是准的（找一个你已知大小的文件核对）
- [ ] 文件夹不会被当成文件列出大小
- [ ] 路径不存在时给提示，不崩

### 卡住看这里

- 报错说文件不存在：路径要写全，或者把文件直接拖进终端里让它自动补全路径
- 大小显示成一大串字节数：忘了换算或忘了保留小数
- 什么都列不出来：路径指向的文件夹是空的，或者你写的是文件路径而不是文件夹

### 常见坑

- 拿自己重要的文件夹（比如桌面、下载）当试验田——**一定要先新建一个空的测试文件夹**
- 路径里带反斜杠导致转义出错，用原始字符串或者正斜杠更省事

## 关卡 2 · 先只预览，不动手

**建议用时**：30 分钟

### 做出这样就算过

对一个装满照片的测试文件夹，程序打印一张对照表：旧名在左、新名在右，新名是按顺序编号的照片_001.jpg、照片_002.jpg 这种，编号补零到三位。**这一步一个文件都不能改。**

### 怎么想（步骤）

1. 先把文件夹里的文件收集成一个列表，只挑文件、跳过文件夹
2. 列表排序（按文件名排，这样每次运行的顺序都一样）
3. 循环里给每个文件算新名字：前缀加补零编号加原来的扩展名。补零要用格式化写法，让 1 显示成 001
4. 扩展名直接从路径对象上取，连点和后缀一起给你，不用自己切
5. 只打印对照表，一个字都不要改名，先看清结果对不对

### 要用到的语法点

- **列表收集与排序**：先把要处理的文件收成列表再排序，保证顺序稳定可预测
- **数字补零**：格式化时指定宽度和补零符号，编号就会对齐成 001、002
- **取扩展名**：路径对象上有现成的属性给你后缀（带点），不用手动切
- **取主文件名**：不带后缀的那部分也有现成属性
- **只打印不改**：把「算新名字」和「改名字」写成两段，先只跑前一段

### 做完了自己检查

- [ ] 对照表里每一行的新名字都是连续的、不重号的
- [ ] 扩展名跟原来一致（jpg 还是 jpg，大小写没变）
- [ ] 编号补零到三位，1 显示成 001
- [ ] 跑完之后去文件夹里看：文件名一个都没变
- [ ] 再跑一次，对照表跟上次完全一样（说明顺序稳定）

### 卡住看这里

- 编号从 0 开始：计数器和编号不是一回事，编号要自己从一开始算
- 扩展名丢了：只取了主文件名却忘了把后缀拼回去
- 对照表顺序每次都不同：忘了排序

### 常见坑

- 觉得「反正就是改个名」直接就开始改——预览这一步是后面撤销功能的基础，别跳过
- 把文件夹也编进编号里

## 关卡 3 · 真改名，并且写下能反悔的记录

**建议用时**：35 分钟

### 做出这样就算过

程序打印预览后问一句「确认改名吗」，输入确认才真的改；改完打印「已改名 8 个」。同时生成一个记录文件，里面每一行都是「旧名 新名」的对应关系。如果有两个文件会撞成同一个新名字，程序要提前发现并拒绝执行。

### 怎么想（步骤）

1. 改名动作用路径对象自带的重命名方法，给它新名字就行
2. 在动手之前先做一次冲突检查：把所有新名字放进一个集合，如果数量比文件数少，说明有重复，直接拒绝并指出是哪几个
3. 另外还要检查新名字是不是已经存在于文件夹里（可能撞上不该动的文件）
4. 每改成功一个，就把「旧名 新名」按固定分隔符写进记录文件。改到一半出错也要保证记录和实际一致
5. 测试三种情况：正常改名、故意造一个重名、路径不存在

### 要用到的语法点

- **重命名**：给一个路径对象一个新名字，它就改好了；新旧文件必须在同一个文件夹里
- **集合去重检查冲突**：把新名字放进集合，集合会自动去掉重复项，数量变少就说明撞了
- **判断文件是否已存在**：改名前先问一句这个名字有没有被占用，避免覆盖别人的文件
- **写入记录文件**：用追加模式一行一条，指定编码；分隔符挑一个文件名里不会出现的符号
- **异常处理**：改名失败（文件被占用、权限不足）时会报错，接住它并提示是哪一个文件失败了

### 做完了自己检查

- [ ] 确认之后真的改名了，去文件夹里核对
- [ ] 记录文件里每行都是「旧名 新名」，行数等于改名个数
- [ ] 故意造重名时程序拒绝执行，并说清是哪几个文件冲突
- [ ] 输入取消时一个文件都不动
- [ ] 改名失败时程序不会静默跳过，会告诉你是哪个文件

### 卡住看这里

- 改名只成功了一部分：把失败的文件和原因记录下来，先看是不是名称里带了不允许的字符
- 重名检查没生效：检查你是拿「新名字集合」和「文件个数」比，还是和「原文件列表」比
- 记录文件里中文变乱码：写入时指定编码

### 常见坑

- 一边遍历文件夹一边改名，导致遍历过程错乱（先把列表算完，再统一改）
- 记录文件写成覆盖模式，第二次运行把第一次的记录冲掉了

## 关卡 4 · 加上撤销和另外两种命名规则

**建议用时**：35 分钟

### 做出这样就算过

程序菜单里有四种操作：1 按序号改名 2 加统一前缀后缀 3 按修改时间排序编号 4 撤销上一次改名。撤销之后，文件夹里的文件名跟没改过之前**完全一致**。

### 怎么想（步骤）

1. 先读记录文件，把每行切成旧名和新名两段，攒成一个列表
2. 撤销就是倒着做一遍：把新名字改回旧名字。倒序遍历很重要——先改回来的可能是后改的，顺序错了会互相撞车
3. 加统一前缀后缀这种规则不需要编号，直接在每个主文件名前后拼字符串（扩展名要保持在最后）
4. 按修改时间排序：取每个文件的修改时间当排序依据，再编号
5. 把这三种规则各做成一个函数，共用同一套「预览 → 确认 → 执行 → 记录」的流程

### 要用到的语法点

- **读文件并解析每行**：逐行读出来，去掉换行符，再按分隔符切分
- **倒序遍历**：撤销要从最后一条记录开始往回做，可以用反转后的列表
- **字符串拼接保后缀**：前缀拼在主文件名前面，后缀拼在后面，扩展名永远在最后
- **按文件属性排序**：排序时可以指定「按什么排」，这里按修改时间
- **多个规则共用流程**：把「怎么算新名字」抽成一个参数，其余流程三种规则完全一样

### 做完了自己检查

- [ ] 三种改名规则都能用，且都能先预览
- [ ] 改完一次再撤销，文件名与原始状态完全一致（用截图或记录文件核对）
- [ ] 连续改两次再撤销，撤销的是最近一次，不是最早的
- [ ] 前缀后缀规则不会把扩展名弄乱（照片.jpg 变成 旅行_照片.jpg）
- [ ] 记录文件不存在时，撤销功能给提示而不是崩

### 卡住看这里

- 撤销之后文件名乱了：多半是正序撤销导致中间撞车，改成倒序
- 前缀加到了扩展名后面：拼接位置放错了，要在主文件名上拼
- 撤销两次的结果不对：记录文件是追加的，撤销完一笔后要把它从记录里去掉或者记下撤销到哪一步

### 常见坑

- 撤销时覆盖了同名文件（撤销前也要做一次冲突检查，跟改名时一样）
- 把记录文件删掉就再也撤不回来了——所以要提醒自己操作前先备份重要文件
