# 029 · 每日一句推送器

> ★★☆☆☆　难度 2.0 / 5　·　021–040 · 联网与窗口
> 3 小时左右，分 4 次　·　1 个文件（daily_quote.py）+ 两个自动生成的数据文件，约 170 行　·　只用 Python 自带功能（tkinter 是自带的）
>
> **规矩：这份任务卡只给思路和语法点，一行代码都没有。代码由你自己写。**

**一句话**：每天取一句随机句子，能收藏、能弹窗提醒、能看历史

## 为什么做它

这是个「没什么用但会一直想用」的小程序——也正因为这样，它是最好的练习素材：小、完整、有真实接口、还能做得挺好看。做完它你会掌握一个小工具的完整生命周期：取数据、存数据、展示、提醒、出错兜底。

## 做完是什么样

运行后取到一句随机句子并显示内容和出处，同时弹一个小窗口提醒你；喜欢的句子可以收藏进文件，随时列出或删掉；同一天再运行不会换句子（每天固定一句）；断网时会从你收藏过的句子里随机挑一句顶上，并说明这是本地内容。约 170 行，一个文件。

## 会练到的语法

`请求接口`　`JSON 取值`　`集合去重`　`文件存读`　`日期比较`　`随机挑选`　`tkinter 弹窗`　`异常降级`　`菜单循环`　`追加历史`

> 新东西是「弹窗提醒」和「同一天只做一次」：前者是图形界面组件最简单的用法，后者需要你把日期存下来跟今天比较。

## 关卡 1 · 先取到一句

**建议用时**：25 分钟

### 做出这样就算过

运行后输出两行：句子内容和它的出处，比如「沙漏我反转了，时间什么时候倒流。—— 网络」。连续运行三次，三次的内容都不一样。

### 怎么想（步骤）

1. 选一个免费的句子接口（搜索「一言 hitokoto 接口文档」，它不需要注册）。先在浏览器里打开一次，看清返回的 JSON 里有哪些字段
2. 请求接口并把返回解析成字典，取出句子内容那个字段打印
3. 再取出处字段一起显示。出处可能有两个字段，一个是作品名、一个是作者，两个都可能为空，要能处理空的
4. 连续运行三次，观察每次都不一样——这就是「随机」在网络服务上的表现
5. 把请求那一步加上超时，接口偶尔会慢
6. 这一关先用异常处理保证：取不到就打印一句提示，程序不崩

### 要用到的语法点

- **请求接口**：返回的是一段 JSON，解析成字典后按字段名取值
- **超时**：请求时带上秒数，避免接口慢的时候卡住
- **处理空字段**：某个字段可能是空的，取值时给默认值，比如「佚名」
- **拼接出处**：作品名和作者拼成一句话，只有一个就只显示那个
- **异常兜底**：网络相关的异常接住，打印提示而不是甩报错

### 做完了自己检查

- [ ] 能显示句子内容和出处
- [ ] 连续三次内容不同
- [ ] 出处字段为空时显示成「佚名」，不会打印出「None」
- [ ] 请求超时或断网时给提示，不崩
- [ ] 中文显示正常，没有乱码

### 卡住看这里

- 取值时报键不存在：字段名跟文档不一致，先打印整个返回看清字段
- 出处显示 None：取值时没给默认值
- 返回内容解不开：先看它到底返回了什么（有的接口在参数不对时会返回网页而不是 JSON）

### 常见坑

- 把接口当成一定会成功的（它可能挂了、可能限流，必须接住失败）
- 不看文档就猜字段名

## 关卡 2 · 做个收藏夹

**建议用时**：30 分钟

### 做出这样就算过

程序菜单有：1 取一句新的 2 收藏当前这句 3 列出所有收藏 4 删掉某一条 5 退出。收藏存在文件里，重启程序还在；同一句不会重复收藏。

### 怎么想（步骤）

1. 收藏的数据结构：每条是一个字典，包含句子、出处、收藏时间；整个收藏是一个列表，存成 JSON
2. 程序启动时读收藏文件（不存在就当作空），退出或在每次修改后写回（建议每次修改就写，别等退出）
3. 收藏时先去重：如果这个句子已经在收藏里，提示「已经收藏过了」
4. 列出收藏：带序号、时间和出处，方便你选；删除时输入序号，并做一次确认
5. 写文件时关掉中文转义、指定编码，不然中文会变成一串编码

### 要用到的语法点

- **列表里放字典**：一条收藏有内容、出处、时间三个字段
- **启动读文件**：先判断文件是否存在，不存在就当空收藏，不要报错
- **去重**：把所有句子做成一个集合，判断新句子在不在里面
- **序号与下标**：显示的序号从 1 开始，取的时候记得换算
- **关掉中文转义**：写 JSON 时关掉它，并且指定编码

### 做完了自己检查

- [ ] 收藏一句后重启程序，收藏还在
- [ ] 重复收藏同一句会被拒绝
- [ ] 列出收藏时有序号、时间和出处
- [ ] 删除时输入序号能删对那一条，输错序号不崩
- [ ] 收藏文件里的中文能直接看懂

### 卡住看这里

- 重启后收藏空了：写文件那一步没被执行（放在退出分支里，但你是强制关闭的）
- 删除删错了：序号和下标差一，取之前先减一
- 文件读不回来：JSON 结构被写坏了，打开文件看一眼最外层是不是列表

### 常见坑

- 用句子内容当文件名去存（内容里有各种符号，很容易出问题；存进一个 JSON 文件最省事）
- 去重时比较大小写和空格（同一个句子可能多一个空格，去掉两头空白再比）

## 关卡 3 · 挑类型，还要有断网预案

**建议用时**：30 分钟

### 做出这样就算过

程序支持指定句子类型（接口支持按类型筛选，比如文学、动画、诗词，具体分类值看接口文档）；如果接口取不到（断网或挂了），自动从收藏夹里随机挑一句顶上，并在输出里说明「本次使用本地收藏」。

### 怎么想（步骤）

1. 先看接口文档里「分类」这个参数怎么传（一般是一个参数名加一个字母或数字），然后在网址里把它拼上
2. 先用浏览器验证：把参数拼进去，看返回的句子是不是真的换了类型（多试几次，能感觉出来）
3. 程序里做成可选参数：不指定就随机，指定了就按类型取
4. 降级逻辑：请求失败时，如果收藏夹里有内容，随机挑一句显示，并标明来源；收藏夹也是空的，才如实说取不到
5. 把「取一句」写成一个函数：返回句子、出处、来源三个信息，主流程只管展示

### 要用到的语法点

- **可选参数**：参数带上就是筛选，不带就是随机；参数名以接口文档为准
- **函数返回多个值**：内容、出处、来源一起返回，调用处一次接住
- **随机挑一个**：从列表里随机取一项，有现成功能
- **分层降级**：先试接口，失败再看收藏夹，都没有才报失败——把顺序写清楚
- **来源标记**：用变量记下这句话从哪来，输出时据此加说明

### 做完了自己检查

- [ ] 指定类型后取到的句子确实属于该类型（多试几次）
- [ ] 断网运行时从收藏夹里随机取，并注明是本地收藏
- [ ] 收藏夹为空且断网时，如实提示取不到
- [ ] 类型参数写错时接口可能会返回默认结果或报错，两种情况程序都要能处理
- [ ] 不带类型参数时行为跟第一关一致

### 卡住看这里

- 指定类型没效果：参数名或取值写错了，先用浏览器验证
- 断网降级没生效：降级分支写在异常处理里面吗，还是写在了异常外面
- 随机挑出来的总是同一句：随机功能的调用写在了循环外面

### 常见坑

- 把降级做成了「悄悄用旧数据」（不告诉用户就换了来源，用户会以为接口还能用）
- 只处理一种失败（接口可能超时、可能返回错误、可能返回的内容格式变了）

## 关卡 4 · 弹窗提醒 + 每天固定一句

**建议用时**：35 分钟

### 做出这样就算过

程序做四件事：1 用一个小窗口把句子显示出来（标题写「今天的一句」）；2 同一天内再运行不会换句子（把今天的句子和日期存进文件，当天直接读出来）；3 每天固定把这一句追加进历史文件；4 菜单里能看最近七天的句子。

### 怎么想（步骤）

1. 弹窗：用自带的图形界面组件弹一个消息框，标题和内容都是你控制的；注意弹窗会阻塞程序，所以逻辑要在弹窗之前做完
2. 每日固定：文件里存「日期 + 句子 + 出处」。启动时先读，日期等于今天就直接用，不等于今天才去取新的
3. 取新句子后立刻写回这个「今日」文件（这样同一天多次运行结果一致）
4. 历史文件：每天追加一条，如果今天已经追加过就不重复追加（判断最后一行的日期）
5. 看最近七天：读历史文件，取最后七行倒序显示

### 要用到的语法点

- **弹窗**：自带组件里有消息框功能，给标题和内容就能弹出来
- **日期字符串比较**：把今天的日期格式化成文字，跟存下来的比；格式统一就好比
- **先算后弹**：弹窗会挡住程序，所有该保存的都先做完
- **追加去重**：追加前先看文件最后一条的日期是不是今天
- **读最后几行**：按行读成列表后切片取最后七项，再反转

### 做完了自己检查

- [ ] 运行后弹出窗口，标题和内容正确
- [ ] 同一天运行两次，句子完全一样
- [ ] 历史文件里同一天只有一条记录
- [ ] 看最近七天能显示出来，最新的在最前面
- [ ] 把「今日」文件手工删掉再运行，会重新取一句（说明降级路径通了）

### 卡住看这里

- 弹窗关不掉或者程序卡住：弹窗必须在所有保存动作之后调用
- 同一天还是换了句子：日期比较没生效，把存下来的日期和今天的日期都打印出来比
- 历史重复追加：判断最后一行日期时没去掉换行符，导致比较不相等

### 常见坑

- 弹窗里显示一长串句子导致窗口撑得很大（太长的内容截断一下）
- 把「今日」文件和历史文件搞混（一个只存今天，一个存所有天）
