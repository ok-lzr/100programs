# 009 · 命令行待办清单

> ★☆☆☆☆　难度 1.0 / 5　·　001–020 · 找回手感
> 3 ~ 4 小时，分 4 次　·　1 个文件（todo.py）+ 1 个数据文件（自动生成），约 170 行　·　只用 Python 自带功能
>
> **规矩：这份任务卡只给思路和语法点，一行代码都没有。代码由你自己写。**

**一句话**：添加、查看、完成、删除待办，关掉程序下次还在

## 为什么做它

这是 001–010 里最重要的一个：它第一次让数据「活过」程序结束。前面九个项目的成果关掉窗口就没了，这个项目的小本子会一直在。做完它，你就掌握了所有带保存功能的程序的核心套路。

## 做完是什么样

运行后是一个菜单：1 添加 2 查看 3 完成 4 删除 5 退出。添加一条待办、关掉程序、再打开，那条待办还在；标记完成的会显示成完成状态；删除掉的不会回来。约 170 行，一个文件，数据存在同文件夹的一个文本文件里。

## 会练到的语法

`列表与字典组合`　`while 菜单循环`　`input 校验`　`列表下标操作`　`函数拆分`　`文件的写与读`　`JSON 或自定义文本格式`　`异常处理`

> 新东西是文件持久化：把列表存成文字，再把它读回来还原成列表。这是本项目最值得慢慢琢磨的一关。

## 关卡 1 · 先在内存里记两条待办

**建议用时**：20 分钟

### 做出这样就算过

运行后程序先问你「要添加什么待办」，你输入一条，它回显这条待办并加上编号；再来一次，能看到两条待办按编号排好。

### 怎么想（步骤）

1. 新建 todo.py，先准备一个空列表当作待办清单
2. 用 input 问一条待办内容，把它加进列表
3. 打印整个清单：每条前面带编号，编号从一开始。用循环带上序号打印，而不是把列表直接打印出来
4. 再加第二条，运行一下看编号是不是 1 和 2
5. 故意输入一个空行，看程序会怎样——记下这个问题，下一关解决它

### 要用到的语法点

- **列表与追加**：往列表末尾加一项用一个现成方法
- **enumerate**：遍历列表时顺手拿到序号；想让编号从一开始，给它指定起始值
- **f-string 拼编号**：把序号插进每条待办前面，看起来像清单
- **len()**：清单为空时长度是 0，可以用它做判断

### 做完了自己检查

- [ ] 添加两条后，打印出来是带编号的两行
- [ ] 编号从 1 开始，不是从 0
- [ ] 清单为空时程序不报错，能提示「还没有待办」

### 卡住看这里

- 打印出来是一堆方括号和引号：那是把整个列表打印了，改成用循环逐条打印
- 编号从 0 开始：默认序号从零起，指定起始值可改成从 1 开始

### 常见坑

- 把输入的空字符串也当成一条待办加进去（下一关要拦掉）
- 把待办直接拼接成一个字符串，后面就无法逐条操作了

## 关卡 2 · 做成一个真菜单

**建议用时**：30 分钟

### 做出这样就算过

程序循环显示菜单，输入 1 进入添加、输入 2 查看清单、输入 5 退出；输入其它内容提示「没有这个选项」并重新显示菜单。程序不会因为一次误输入就退出。

### 怎么想（步骤）

1. 把菜单文字和选项列出来，写成一个函数，每次循环都调用它显示
2. 主流程是一个永远成立的循环：显示菜单 → 拿用户的选择 → 用 if / elif 分派到不同动作 → 回到循环开头
3. 选 5 的时候用跳出循环的方式退出，退出前打印一句道别
4. 添加功能里加校验：内容去掉两边空白后如果是空的，提示「内容不能为空」并且不添加
5. 查看功能里加判断：清单为空时提示还没有待办，不为空时按编号列出

### 要用到的语法点

- **while True 主循环**：菜单类程序的骨架就是一个永不结束的循环加一个退出分支
- **if / elif 分派**：按用户输入走不同分支，最后一个 else 处理非法输入
- **字符串去空白后判断为空**：用户可能只敲了空格，去掉空白后长度为 0 才算真的空
- **函数拆分**：显示菜单、添加待办、查看清单各写一个函数，主循环里只有分派逻辑

### 做完了自己检查

- [ ] 选 1 添加后菜单会重新出现
- [ ] 选 2 能看到刚才添加的内容
- [ ] 选 5 干净退出
- [ ] 输入 9 或 abc 会提示没有这个选项，程序继续运行
- [ ] 输入只有空格的待办内容会被拒绝

### 卡住看这里

- 菜单只显示一次就退出了：检查主循环有没有真的包住整个流程，缩进对不对
- 添加完菜单不回来：添加函数里不小心也写了退出
- 判断空内容时用了长度判断但没去空白，导致空格能通过

### 常见坑

- 把每个功能都塞进一个巨大的 if 里，几百行挤在一起（拆函数）
- 用户输入的选择没有去掉多余空格，导致「 1 」不被识别

## 关卡 3 · 能完成，也能删掉

**建议用时**：35 分钟

### 做出这样就算过

菜单变成五项：1 添加 2 查看（每条前面显示序号和状态，未完成显示方块或方框，已完成显示对勾） 3 标记完成 4 删除 5 退出。标记完成要输入序号；删除前要确认一次，确认了才真的删。

### 怎么想（步骤）

1. 每条待办不能只是一句话了，需要携带状态。用一个字典来表示一条待办，字段包括编号、内容、是否完成
2. 改写查看功能：逐条打印时带上状态符号，已完成的排在最后或者用符号区分都行，规则你定
3. 标记完成：让用户输入序号，找到对应那条，把状态改成已完成；序号不存在要提示
4. 删除：输入序号后先显示这条待办的内容，问一句「确定删除吗」；用户输入 y 才删
5. 删完之后检查编号是否还连续——如果用的是列表下标，删掉中间一条后面的编号会自动变，这在待办清单里其实没问题，但你要能说清楚为什么

### 要用到的语法点

- **列表里放字典**：一条记录有多个属性时，字典比元组好读；整个清单就是字典的列表
- **按下标取和改**：用户输入的序号是从 1 开始的，而下标从 0 开始，别忘记减一
- **删除列表元素**：有两个功能，一个按位置删一个按值删，这里用按位置删
- **二次确认**：把用户输入转成小写再比较，y 和 Y 都算确认
- **下标越界保护**：用户可能输入一个超过清单长度的序号，先判断范围再取，或者用异常接住

### 做完了自己检查

- [ ] 标记完成后查看，那条显示为已完成
- [ ] 对已完成的条目再标记一次不会出错（可以选择忽略或者提示）
- [ ] 删除时输 y 才真删，输 n 什么都不发生
- [ ] 输入不存在的序号（0、99、abc）都有提示且不崩
- [ ] 清单为空时选 3 或 4 会提示而不是报错

### 卡住看这里

- 输入 1 却删掉了第二条：忘了把序号减一，或者序号是从 0 开始显示的
- 序号越界报错：取之前先检查序号在合法范围内
- 改成字典之后查看功能全乱了：检查取值时用的键名跟定义时是否一致

### 常见坑

- 在遍历列表的同时删除元素，导致漏项（要删就先记下来，遍历结束再删）
- 用字符串表示完成状态（比如把状态写成「是」或「否」这样的文字），比较时容易因为空格或大小写出错，改用真假值更稳

## 关卡 4 · 关掉程序，下次还在

**建议用时**：35 分钟

### 做出这样就算过

程序启动时自动读取数据文件，把上次的待办全部显示出来；每次增删改之后立即写回文件。删掉数据文件再运行，程序要能正常从空清单开始，不报错。

### 怎么想（步骤）

1. 选一种保存格式。最简单的是每行一条、字段之间用固定符号分隔；更规范的是用 Python 自带的 JSON 格式，它能直接把列表和字典原样存成文字再读回来
2. 写一个保存函数：把整个清单写进文件（覆盖写，因为每次都是完整保存）
3. 写一个读取函数：文件存在就读取并还原成列表；文件不存在就返回一个空列表
4. 在合适的位置调用保存：添加、标记完成、删除之后各调用一次；启动时调用一次读取
5. 测试四件事：添加后重启、完成状态重启后还在、删除后重启不会复活、把数据文件删掉再启动不报错

### 要用到的语法点

- **JSON 的存与读**：自带的 json 功能可以把列表字典和文字互相转换，中文要注意别被转成乱码符号
- **文件存在判断**：先判断文件在不在，再决定读还是返回空列表，比直接用异常接住更直观
- **写入时的编码**：指定 UTF-8，中文待办才不会变乱码
- **覆盖写与追加写的选择**：整体保存用覆盖写；追加写适合日志类只增不改的记录
- **异常兜底**：文件内容被手动改坏了会读失败，接住异常并告诉用户「数据文件读不了」，别直接崩

### 做完了自己检查

- [ ] 添加两条 → 退出 → 重新运行，两条都在
- [ ] 标记完成 → 重新运行，完成状态还在
- [ ] 删除一条 → 重新运行，被删的没有复活
- [ ] 手动删掉数据文件 → 运行正常，从空清单开始
- [ ] 数据文件里的中文打开后不是乱码

### 卡住看这里

- 读回来变成一串字符而不是列表：JSON 转换只做了一半（存的时候转了，读的时候忘了转回来）
- 启动就报文件不存在的错：读取函数里要先判断文件在不在
- 中文变成类似反斜杠加字母的东西：转换时关掉默认的编码转换，直接存成中文
- 改了数据但没保存：检查每个改动分支后面是不是都调了保存

### 常见坑

- 只在退出时保存一次——万一程序被强制关掉，这一轮的操作全丢；改动后就保存更稳
- 保存时用了追加模式，导致每次保存都往文件尾部再加一整份清单，越读越乱
