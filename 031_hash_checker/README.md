**一句话**：算出文件的指纹，检查文件有没有被改过、下全了没有

## 为什么做它

下载一个大文件时，网站上常常会给出一个又长又乱的字符串，让你核对——那就是文件的指纹。指纹有两个用途：一是**判断文件有没有被改动**（哪怕改一个字节，指纹完全变样），二是**确认下载完整**（传丢一小段，指纹就对不上）。这个项目做完，你就有了一个能自己验证文件完整性的工具。

## 做完是什么样

程序有三种用法：算一个文件的指纹、拿一个指纹去校验文件对不对、把一个文件夹里所有文件的指纹做成一张清单；还能拿两张清单对比，找出哪些文件被改过、哪些是新增的。约 170 行，一个文件。

## 会练到的语法

`import hashlib`　`分块读取文件`　`十六进制字符串`　`字符串比较`　`目录遍历`　`清单文件读写`　`两表对比`　`命令行参数`　`异常处理`　`报告输出`

> 新东西是「哈希」：一种把任意长的内容压成固定长度指纹的办法。它有三个性质值得记住——同样内容指纹一定相同、改一点就完全不同、从指纹倒推不出内容。

## 关卡 1 · 先算出一个指纹

**建议用时**：25 分钟

### 做出这样就算过

运行后输出一个文件的指纹，比如「A3F1...（64 位十六进制）」，连同文件名和大小一起打印。把文件内容改一个字再算一次，指纹应该完全不同（前几位就变了）。

### 怎么想（步骤）

1. 新建 hash_check.py，引入自带的哈希功能，选一种常用算法（sha256 是现在最常用的）
2. 不要一次把整个文件读进内存：分块读（比如每次 64KB），读一块就把内容喂给哈希对象
3. 全部读完后再向哈希对象要最终的指纹字符串
4. 打印指纹、文件名、文件大小；指纹统一转成小写或者大写（自己定，但要一致）
5. 验证：改文件里的一个字（比如加一个空格），重新算，对比两次指纹

### 要用到的语法点

- **创建哈希对象**：先用算法名造一个对象，再把内容一段段喂给它
- **分块读取**：用二进制方式打开文件，一次读固定长度，读到空内容就停
- **喂数据**：哈希对象有一个更新方法，读一块喂一块
- **取指纹**：全部喂完后要一个十六进制字符串，那就是指纹
- **文件大小**：路径对象上的 stat 里有大小字段

### 做完了自己检查

- [ ] 同一个文件算两次，指纹完全一样
- [ ] 改一个字符后指纹完全不同
- [ ] 两个内容相同但文件名不同的文件，指纹相同（说明指纹只看内容）
- [ ] 算一个几十兆的文件时内存没有明显上涨（说明是分块读的）
- [ ] 文件不存在时给提示，不崩

### 卡住看这里

- 指纹每次算出来都不一样：哈希对象建在了循环里面，每块都重新开始了
- 内存占用很高：用了「一次读完」的写法，改成分块
- 中文文件名出错：用路径对象处理，别自己拼字符串

### 常见坑

- 拿 md5 当唯一标准去判断「文件是否安全」（md5 已经被证明可以人为造出相同指纹，安全用途要用 sha256 以上）
- 把文件名也算进哈希（那样内容相同、名字不同的文件就判不出一样了）

## 关卡 2 · 拿指纹去校验

**建议用时**：30 分钟

### 做出这样就算过

程序能接收「文件路径 + 一个指纹」，判断是否一致：一致输出「校验通过 ✓」，不一致输出「校验失败 ✗，实际是 xxxx」。指纹输入时带不带空格、大写小写都要能正确处理。

### 怎么想（步骤）

1. 把指纹处理得健壮一点：去掉两头的空白、中间的换行、统一转成小写再比较——很多网站贴出来的指纹是带空格分组的
2. 算文件的指纹，跟给定的比，输出结果
3. 支持指纹来自文件：很多下载站会给一个校验文件，里面一行是「指纹 文件名」，程序要能读它并只取指纹那一段
4. 不一致时把「期望的」和「实际的」都打印出来，并且把第一个不同的位置标出来，方便看是不是复制少了几位
5. 测试四种情况：完全一致、少复制了几位、有多余空格、大小写不同

### 要用到的语法点

- **字符串清理**：去掉空白、去掉换行、统一小写，几行就能把指纹洗干净
- **切分取第一段**：校验文件里一行是「指纹 文件名」，按空白切分后取第一项
- **字符串相等比较**：两个字符串相等就用两个等号；注意不能有看不见的空格
- **找第一个不同的位置**：逐个字符比较，第一次不一样就记下位置（这个提示对排查很有用）
- **读校验文件**：按行读，跳过空行，只取第一行或者全部行第一项

### 做完了自己检查

- [ ] 一致的指纹显示通过
- [ ] 把指纹里任意一位改掉，显示失败并标出第一位不同的位置
- [ ] 带空格的指纹（每八位一个空格）能正确识别
- [ ] 大写指纹能正确识别
- [ ] 校验文件不存在或格式怪异时给提示，不崩

### 卡住看这里

- 明明一样却报失败：指纹里混了换行符，比较前先清理
- 位置标错：你比较的是清理前还是清理后的字符串，注意顺序
- 读校验文件读出了文件名：没取第一段，把整行都当指纹了

### 常见坑

- 用字符串包含来判断（只要你的指纹是对方指纹的一部分就会被误判成通过）
- 把「失败」当成程序出错（校验失败是正常结果，是文件的问题，不是程序的问题）

## 关卡 3 · 给一整个文件夹做清单

**建议用时**：35 分钟

### 做出这样就算过

程序扫描一个文件夹，给每个文件算指纹，写出一份清单文件：每行是「指纹 相对路径」。清单生成后能用它校验：把清单和文件夹一起检查，输出哪些文件对得上、哪些对不上、哪些文件在清单里但已经不在了。

### 怎么想（步骤）

1. 遍历文件夹（只处理文件，跳过文件夹），逐个算指纹
2. 清单格式定成「指纹 两个空格 相对路径」——相对路径很重要，这样文件夹换个位置清单还能用
3. 写清单文件时指定编码；顺便在文件头写一行注释说明生成时间和算法
4. 校验功能：读清单的每一行，算对应文件当前的指纹，比对；结果分三类收集（通过、不匹配、文件缺失）
5. 最后打印汇总：共多少文件、通过多少、不匹配多少、缺失多少

### 要用到的语法点

- **相对路径**：相对于清单所在文件夹的路径，比绝对路径更适合交换使用
- **跳过注释行**：以井号开头的行不当数据
- **逐个算指纹**：复用第一关的函数，不要在循环里重写一遍
- **分类收集**：三个列表分别装通过、不匹配、缺失的文件
- **汇总打印**：最后统一打印数量和名单

### 做完了自己检查

- [ ] 清单文件里每个文件一行，指纹和路径齐全
- [ ] 改掉其中一个文件后校验，只有那一个报不匹配
- [ ] 删掉一个文件后校验，它被列进缺失名单
- [ ] 新增的文件不会出现在校验结果里（清单里没有它）
- [ ] 文件夹里嵌套的子文件夹也能被扫到

### 卡住看这里

- 路径太长或者带盘符很乱：用相对路径，显示和保存都用它
- 校验时找不到文件：清单里的路径是相对路径，要拼上清单所在目录才是完整路径
- 注释行被当成数据：读取时没跳过井号开头的行

### 常见坑

- 清单里存绝对路径（换台电脑或者文件夹挪个位置就全废了）
- 把清单文件自己也算进清单（每次生成清单都会变，永远对不上）

## 关卡 4 · 对比两份清单，做成完整工具

**建议用时**：35 分钟

### 做出这样就算过

做成带参数的命令行工具：可以算单个文件、校验清单、生成清单、对比两份清单。对比时输出四类结果：新增的文件、消失的文件、内容被改过的文件、没变的文件数量。所有命令都能用运行参数调用，参数写错时打印用法说明。

### 怎么想（步骤）

1. 设计参数：第一个参数是「做什么」（用英文单词，比如算、校验、生成、对比），后面是它需要的文件或路径
2. 把四个功能各写成一个函数，主流程只负责看参数分派；参数不够或者不认识时打印用法说明并退出
3. 对比两份清单：两份都读成「路径对应指纹」的字典，然后用集合运算找出新增、消失的路径；交集里的路径再逐个比指纹
4. 输出对比报告：四类结果分开列，内容改过的要显示前后的指纹（截取前八位就够看）
5. 加一个退出码约定：全部通过返回 0，发现不一致返回 1——这样以后能把你的工具接到别的程序里自动判断

### 要用到的语法点

- **分词与取值**：从运行参数里按位置取，取不到就打印用法
- **函数分派**：用一串判断把「做什么」翻译成调用哪个函数
- **集合运算**：两份路径集合相减得到各自独有的，取交集得到共同的
- **字典取值**：路径当键、指纹当值，查起来最直接
- **退出码**：结束时告诉系统一个数字：0 表示一切正常，非 0 表示有问题

### 做完了自己检查

- [ ] 四种功能都能用参数调用
- [ ] 参数写错时打印用法说明，不是甩一堆报错
- [ ] 两份清单对比的结果四种情况都准确
- [ ] 校验全部通过时退出码是 0，有不一致时是 1（可以在命令行里查一下退出码）
- [ ] 整个工具对同一个文件夹跑一遍，行为和前面各关一致

### 卡住看这里

- 参数顺序记不住：把用法说明写得具体一点，带上例子
- 对比时把没变的也列出来了：只列变化的三类，没变的只报数量
- 退出码没生效：要主动结束程序并带上那个数字

### 常见坑

- 把「做什么」写成中文（命令行里容易因为编码出问题，用英文更稳）
- 四个功能各写一份重复的算指纹代码（抽成一个函数）
