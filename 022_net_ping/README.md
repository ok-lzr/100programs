# 022 · 网络连通性检测器

> ★★☆☆☆　难度 2.0 / 5　·　021–040 · 联网与窗口
> 3 小时左右，分 4 次　·　1 个文件（net_ping.py），约 160 行　·　只用 Python 自带功能
>
> **规矩：这份任务卡只给思路和语法点，一行代码都没有。代码由你自己写。**

**一句话**：测某个地址通不通、要多久，能连续监测并出报告

## 为什么做它

网一卡，你第一反应是「是不是我网的问题」。这个程序让你能自己回答这个问题：连续测几十次，看成功率和延迟抖动——网课卡的时候，你能拿出数据说「过去一分钟有 12 秒是断的」，而不是凭感觉。它也是你第一次跟「网络」打交道：连接、超时、延迟，这些词以后会一直出现。

## 做完是什么样

程序里有一个目标列表（本机、自己家的路由器、公共 DNS 服务器），可以测一次给出「通/不通 + 耗时多少毫秒」，也可以连续监测几十次，最后给一份报告：成功率、平均延迟、最慢一次、抖动多大。约 160 行，一个文件。

## 会练到的语法

`import socket`　`建立连接`　`超时设置`　`connect_ex 的返回值`　`time.time 计时`　`循环采样`　`平均值与最大最小`　`异常处理`　`列表统计`　`报告组装`

> 新东西是「连接」这件事本身：程序可以主动去连一个地址的某个端口，连上了说明通、耗时就是延迟。超时设置是这一关的关键——不设超时，程序会卡到你以为死机。

## 关卡 1 · 先测一次：通还是不通

**建议用时**：25 分钟

### 做出这样就算过

运行后输出「本机 127.0.0.1 的 80 端口：不通」和「本机 127.0.0.1 的 135 端口：通」这样的结果（具体哪些端口通取决于你的电脑）。然后拿 223.5.5.5 的 53 端口试一次，应该输出通。

### 怎么想（步骤）

1. 新建 net_ping.py，引入自带的网络功能
2. 建一个网络连接对象，设置一个超时时间（比如两秒）——**这一步是这一关最重要的**，不设的话连接失败时程序会卡几十秒
3. 尝试去连接一个地址的某个端口，用一个专门的方法：它不会因为失败就报错，而是返回一个数字，0 表示成功，别的数字表示各种失败原因
4. 根据返回值打印「通」或者「不通」。先测本机 127.0.0.1 的几个端口，把结果记下来
5. 再测公共 DNS 服务器的 53 端口（这是域名解析服务，通常是开着的，可以用来验证你的程序在真实网络上也能工作）

### 要用到的语法点

- **import socket**：自带的网络模块，建立连接、查域名都靠它
- **建立连接对象**：要先说明用哪种方式连接（TCP）
- **设置超时**：给连接对象设一个超时秒数，连不上就放弃，不会无限等待
- **不带异常的连接尝试**：有一个方法专门用来「试连」，返回 0 表示成功，非 0 表示失败原因码，不会抛异常
- **用完关闭**：连接对象用完要关闭，否则反复测试会占满资源

### 做完了自己检查

- [ ] 本机某个没人用的端口报「不通」，这是对的
- [ ] 如果你本机有服务在监听某个端口（比如你自己起的网页服务），它报「通」
- [ ] 223.5.5.5 的 53 端口报「通」，耗时通常几十毫秒
- [ ] 测一个不存在的地址时，程序在超时时间内返回「不通」，不会卡住
- [ ] 反复测十次不报错（说明连接对象关得干净）

### 卡住看这里

- 程序卡住不动：忘了设超时，或者地址写成了一个不可达的 IP
- 所有端口都报通：返回值判断写反了（0 才是成功）
- 报错说地址不对：IP 格式写错了，或者把端口和地址写反了

### 常见坑

- 不设超时（这是新手最常见的坑，会让程序看起来像死机）
- 拿别人的网站或服务器乱测（**只测自己的电脑、自己的路由器、公共 DNS 这类专门给大家用的服务**）

## 关卡 2 · 测出耗时：延迟和抖动

**建议用时**：30 分钟

### 做出这样就算过

程序对一个目标连续测 5 次，每次打印耗时（毫秒，保留一位小数），最后输出一行汇总：平均 23.4 毫秒、最快 18.2、最慢 41.7、抖动 23.5 毫秒。

### 怎么想（步骤）

1. 在连接前后各取一次时间戳，两次相减就是这一次的耗时（单位是秒）
2. 把秒换算成毫秒：乘以 1000，打印时保留一位小数
3. 用一个循环测 5 次，每次的耗时都收集进一个列表
4. 汇总：平均值用总和除以次数；最快最慢用现成的最大最小功能；抖动就是最慢减最快
5. 测失败的次数要单独统计——失败的不能算进平均耗时里，否则结果没意义

### 要用到的语法点

- **取时间戳**：取一个当前的秒数（带小数），前后各取一次相减就是耗时
- **秒换算毫秒**：乘以 1000；打印时保留一位小数
- **列表收集与求和**：每次的耗时加进列表，最后统一算平均
- **最大最小**：列表有现成的最大值最小值功能
- **分开统计成功与失败**：失败的那次不要往耗时列表里加，单独记一个失败次数

### 做完了自己检查

- [ ] 五次耗时都打印出来了，单位是毫秒
- [ ] 平均值介于最快和最慢之间
- [ ] 抖动等于最慢减最快（自己拿数字核对一次）
- [ ] 如果中间有一次失败，平均耗时不会因此变得很怪
- [ ] 连测公共 DNS 时，耗时一般在几十毫秒量级（如果你测出来几百毫秒，多半是网络本身的问题，不是程序错）

### 卡住看这里

- 耗时全是 0.0：取时间戳的位置写错了，前后取到了同一个时刻（要在连接前后各取一次）
- 耗时显示成好几万毫秒：单位换算多乘了一次，或者没乘够
- 平均值算错：把失败次数也当成了 0 毫秒加进去了

### 常见坑

- 把失败的那次当作耗时 0 参与平均（结果会被严重拉低）
- 只测一次就下结论（网络延迟本来就抖，一次说明不了问题）

## 关卡 3 · 一次测一批目标，输出表格

**建议用时**：30 分钟

### 做出这样就算过

程序里放一组目标（本机、路由器、公共 DNS 若干个，每个带地址和端口），运行后对这组目标各测 3 次，输出一张对齐的表格：目标名、地址、状态、平均延迟，最后打印「4 个目标，3 个通」。

### 怎么想（步骤）

1. 把目标写成一个列表，每一项是字典：名字、地址、端口。起几个好记的名字（本机、路由器、阿里 DNS、腾讯 DNS）
2. 对每个目标调用你上一关写好的测试逻辑；把「测 3 次」也做成一个函数，返回平均耗时和成功率
3. 打印时对齐：名字和地址都是文字，用固定宽度格式化让列对齐（中文宽度和英文不一样，差一点点没关系，看着整齐就行）
4. 状态列显示「通」「不稳定」（3 次里成功 1 到 2 次）「不通」三种，比只分通不通更有信息量
5. 最后统计有几个目标是完全通的，打印汇总

### 要用到的语法点

- **列表里放字典**：一组目标，每个目标有名字、地址、端口三个字段
- **函数返回多个结果**：测试函数可以同时返回平均耗时和成功率，调用处一次接住两个
- **固定宽度格式化**：格式化时指定宽度，内容不够就补空格，表格就能对齐
- **三态判断**：按成功次数分成通、不稳定、不通三种情况
- **汇总统计**：遍历结果列表，数一数完全通的有几个

### 做完了自己检查

- [ ] 表格的列是对齐的，能一眼看出每个目标的状况
- [ ] 本机目标的行为符合预期（你自己起的服务应该显示通）
- [ ] 不稳定状态能被正确识别（可以把端口改成一个偶尔不通的目标来试）
- [ ] 汇总数字等于表格里完全通的行数
- [ ] 整个列表跑完的时间在合理范围内（每个目标最多等两秒超时）

### 卡住看这里

- 表格怎么都对不齐：中文占两个字符宽度而格式化只按一个算，接受一点点错位，或者统一用英文名
- 某个目标把整个程序拖得很慢：超时设太长了，改成两秒
- 状态判断写错：注意 3 次里成功 0 次才是「不通」

### 常见坑

- 把目标列表写成了别人的服务器（**只放自己的设备和你明确知道是公共服务的地址**）
- 每个目标只测一次就下结论（本来就该多测几次）

## 关卡 4 · 连续监测，出一份能拿给人看的报告

**建议用时**：35 分钟

### 做出这样就算过

程序支持连续监测模式：每隔一段时间测一次，一直测指定的次数（比如 20 次），屏幕上每次刷新一行当前状态，结束时打印一份报告并写进文件：总次数、成功次数、成功率、平均延迟、最慢一次、抖动、以及「连续失败最长的有几次」。

### 怎么想（步骤）

1. 把「测一轮所有目标」包进一个大循环，循环之间用等待功能隔开（别空转）
2. 记录每一轮的结果：成功还是失败、耗时多少。这些数据攒起来后面统计用
3. 算「连续失败最长」：遍历结果，遇到失败就累加、遇到成功就清零并更新最大值
4. 报告先攒成几行文字，再同时打印和写文件；写文件时带上开始时间和结束时间，这样报告才有意义
5. 加中断处理：中途按键停止时，把已经测到的数据照样汇总成报告，而不是丢掉

### 要用到的语法点

- **嵌套循环**：外层是轮次，内层是每个目标；注意两层变量别重名
- **等待间隔**：每轮之间等一会儿，别让程序满负荷空转
- **连续计数**：一个当前连续数、一个历史最大数，遇到成功就清零当前数
- **中断处理**：接住中断键的异常，在分支里照样输出报告
- **报告写文件**：指定编码，把攒好的几行用换行连起来写进去

### 做完了自己检查

- [ ] 连续跑 20 轮后报告里的数字跟过程打印对得上
- [ ] 成功率等于成功次数除以总次数（自己验算一次）
- [ ] 连续失败最长的数字能被正确算出（中途拔网线试一次最直观）
- [ ] 中途按键停止时会输出报告，而不是什么都不剩
- [ ] 报告文件能打开，中文不乱码，带开始和结束时间

### 卡住看这里

- 报告里的总次数不对：每轮测了多个目标时，总数应该是轮数乘目标数
- 中断后程序报错退出：中断处理里访问了还没赋值的变量，注意初始化位置
- 连续失败最长一直是 1：忘了在成功时把当前连续数清零

### 常见坑

- 报告里不写时间（那样的数据没法用）
- 把中断当成出错，让它把已经测到的数据全丢了
